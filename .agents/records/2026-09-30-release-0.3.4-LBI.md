## 本轮踩坑

1. **`python` stub exit 49（与 0.3.3-LFC 记录同款，复发）**：PATH 上的 `python` 仍是 Microsoft Store 占位 stub；且 0.3.3 时可用的 `~/.local/bin/python3.12.exe` 本次探明 `py` launcher 默认指向已损坏的 `F:\Python\python.exe`（Unable to create process）。本次改用 uv 托管解释器 `AppData\Roaming\uv\python\cpython-3.12.13-…\python.exe`，并把**该目录整体前置到 PATH** 再跑构建链，使 `pack:portable` 内的裸 `python` 也解析到真解释器。首构建轮死于 Rust 全链成功后的打包步（exit 49），PATH 修正后重跑（全链增量）EXIT=0。
2. **幻影改动阻断切分支（与 0.3.3-LFC 记录同款，复发）**：合并后切 `main` 被 `src-tauri/Cargo.toml` 的 M 状态拦下，`git diff` 为空（stat 缓存脏），`git checkout --` 还原后正常。
3. **本地预演 zip 混入旧构建残留（新发现）**：本地 manifest 304 项 vs CI 282 项，差的 22 项全为 `resources/docs-site/assets/` 下历史构建的哈希变体 chunk（`app.*.js`×3 代、`theme.*.js`×3 代等）——`stage-docs-site.mjs` staging 不清旧产物，本地反复构建会累积。CI 全新 checkout 不受影响，**Release 资产正确**；已登记 issue 跟踪 staging 清理。
4. **`.sha256` CRLF 已知问题的绕过**：本轮验收改用 `gh release download` 落地后直接读文件内容比对（不经 `sha256sum -c`），未触雷；该已知问题仍未修（承接 0.3.3 记录，留给后续）。
