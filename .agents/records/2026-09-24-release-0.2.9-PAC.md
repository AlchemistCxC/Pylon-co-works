## 方案要点

1. **合并顺序**：先 `git status` 确认工作树干净（无他人在途改动、无 `MERGE_HEAD`），再 `git merge github/main`。
   本次**无冲突**——`main` 侧与 `kumo/prometheus` 侧未触碰同一文件域，`.agents/L.md` 也未撞车。
2. **版本号落地面**：`pack_release.py::resolve_version()` 强校验 `package.json` / `tauri.conf.json` /
   `Cargo.toml` 三处一致，不一致直接 `PackError`；故三者必须同改。`Cargo.lock` 手工同步而非依赖
   cargo 自动重写，避免「构建顺带改锁文件」这种隐式改动混进提交。
3. **构建用既有编排**：`bun run release:portable`，不手工拆步——该脚本就是既有发行路径，
   且末尾 `pack:portable` 自带 `verify_zip`（manifest 与 ZIP 内容逐项比对）。
4. **`webview2-mcp.exe` 未重新链接是正常的**：该独立 crate 源码最后变更在 2026-09-21（`79e2e16f`），
   早于上次发行构建，cargo 判定 fresh（`Finished in 0.30s`），产物沿用旧时间戳。曾专门复验确认非陈旧。
