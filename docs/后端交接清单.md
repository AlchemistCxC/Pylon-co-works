## 5. source → periId → generation

```text
source：Pylon 本地 sessions map key
periId：ACP 远端 sessionId
 generation：ACP client 代际
```

权威映射：

```text
source → SessionInfo { peri_id, generation, cwd, ... }
```

约束：

- Peri `session/update` 不携带 Pylon source。
- source 通过本地 `periId → source` 映射恢复。
- 不得把同一个本地 source 变量重复传给 helper，包装成独立 event source 证据。
- timeout、load failure、close、stale response 清理必须匹配 `source + periId + generation`。
- 成功 Agent replacement 后 generation 递增。
- 连接失败不得递增 generation。

### 7.2 ACP/Peri session replay

当前实现：

```text
建立 broadcast receiver
→ 注册 pending
→ 发送 session/load
→ 收集目标 session 的 session/update
→ 等待 response
→ response 作为 replay 边界
→ 返回 response + replay
```

已处理：

- `mcpServers` 显式存在。
- reader 先 broadcast，再完成 response pending。
- 目标 session 过滤。
- `Lagged`、`Closed`、timeout、RPC error 返回明确错误。
- load failure/generation stale 恢复旧 Session mapping。
- export 使用同一 replay 路径，禁止固定 sleep。

未验收：

- fake ACP 大历史集成压力。
- 真实 Peri session/load 抓包。
- 真实导出文件完整性。
- collector 大历史消费边界。

### 7.3 Agent replacement 静态边界

`replace_agent_client` 当前顺序：

1. 检查新 client 未 crashed。
2. 在 ACP async lock scope 内获取 active agent 和 sessions 同步锁。
3. swap 新 client。
4. 递增 generation。
5. 更新 active agent。
6. 清空 sessions。
7. 释放状态锁。
8. 重启 notification dispatcher。
9. `kill + wait` 旧 client。

新连接/initialize 失败时不会进入 replace，旧 client、active agent、sessions、generation 保持不变。

未验收：

- fake ACP 失败切换回滚。
- 新旧 child PID 退出证据。
- 真实 Tauri switch/reconnect。
- switch/reconnect 期间并发 prompt 的行为。

### 7.4 Agent config reload

已有：

- agents.yaml 非空检查。
- id/name/exe/transport 字段检查。
- `reload_agents` 与 switch/reconnect 共用 lifecycle lock。
- active agent 不得被新配置移除。
- 失败不覆盖旧 registry。
- 成功日志只记录 `agentCount`。
- reload 不自动 reconnect 当前 Agent。

已验证：

- 当前 generation 内唯一 `periId` 映射可解析到 source + generation。

- 仅存在旧 generation mapping 时不解析。

- 完整 `cargo test --lib` 当前通过 55 项，focused fake ACP 当前通过 11 项。

- 真实 fake ACP 多 session 并发交错通知/response。
