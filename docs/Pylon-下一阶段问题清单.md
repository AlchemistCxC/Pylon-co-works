## 1. 流式输出节奏

- **现状**：事件到达后，Solid renderer 直接消费最新快照；高密度 token 可能在同一帧内成批出现，视觉上像“涌入”或跳变。
- **目标**：设置渲染更新速率上限，保留完整原文，在显示层以逐字或极小粒度平滑追赶；终态必须立即完整落地。
- **调查入口**：`agentWorkbenchSession`、`WorkbenchRuntime`、`mountSolidWorkbench`、Solid 消息/Markdown 渲染链路。

## 2. terminal-like 块间距统一

- **现状**：助手正文、思考、工具/活动等块由不同组件和预设分别控制，块间距可能随视觉预设漂移。
- **目标**：块间距由终端 like 骨架统一提供；预设只决定块内行高、字体和材质。
- **调查入口**：Workbench/Chat CSS、消息行与活动行的外层结构、Presentation Profile token。

## 3. 本机 ACP Agent 运行时探测

- **现状**：本机兼容 Agent 的识别存在误探，探测结果与实际可用能力可能不一致。
- **目标**：重做探测协议和置信度分层，区分“发现”“可启动”“可完成握手”，减少误报并保留可诊断证据。
- **调查入口**：Agent detector、ACP 启动/握手、状态缓存与重试策略。

## 4. 连续同种工具调用聚合

- **现状**：连续的同类工具调用逐张展示，重复信息占用大量纵向空间。
- **目标**：相邻同种调用先聚合为缩略组，显示次数和摘要；支持组级、单次级逐级展开，详细内容不丢失。
- **调查入口**：Workbench activity projection、工具卡、活动排序/父子关系和展开状态持久化。

## 5. MCP、Skill、插件设置管理

- **现状**：工作区设置仍有逗号分隔文本输入，信息展示、启停和配置入口分散且可观察性不足。
- **目标**：在设置页以结构化列表管理（新建、编辑、删除、启停、错误状态），工作区设置用便捷选择器引用启用项。
- **调查入口**：插件/MCP/Skill schema、workspace settings store、配置迁移与权限边界。

## 6. 全局设置页面重组

- **现状**：存在重复设置项及中英文重复标签，分区和命名不够直观。
- **目标**：去重、统一术语、按用户任务重组分区，让每个选项只有一个清晰归属和名称。
- **调查入口**：全局设置注册表、各设置页贡献、旧键迁移和搜索索引。

## 7. Agentsheet 空态与创建会话形态

- **现状**：空态创建配置页偏高、偏表单化，和聊天输入台的关系不够自然。
- **目标**：重做空态展示；创建会话配置改为更长更矮、类似输入栏的形态，保持无圆角/安静仪器语气，并确保创建行为不变。
- **调查入口**：`WorkbenchEmptyState`、会话创建命令、空态 CSS 与不同 workspace mode。

## 8. Filesheet 语言插件与 Git

- **现状**：语言能力主要由内置目录覆盖；Git 常用操作和性能仍有缺口。
- **目标**：开放可导入语言包接口（高亮、补全、格式化等），补齐常用 Git 操作并优化扫描/差异/状态路径，接近 Zed 的响应速度。
- **调查入口**：FileSheet/CodeMirror adapter、插件注册边界、Git 命令 facade、工作区缓存与取消机制。

## 9. 输入内容预测

- **现状**：尚无完整的 Claude Code 风格输入预测体验，预测与实际发送/编辑状态的边界需要定义。
- **目标**：借鉴其低打扰的预测提示，支持接受/拒绝、编辑后失效、隐私与本地/远端策略可控。
- **调查入口**：输入台状态机、assist prediction 事件、键盘交互和模型/缓存策略。

## 进入施工的共同门槛

1. 先确认现有语义数据和命令边界，不把视觉问题改成协议重写。
2. 优先建立可回滚的窄 seam，再扩大到跨组件迁移。
3. 事实数据、持久化和渲染显示分层；显示优化不得丢失或改写事实。
4. 每项施工书另列兼容性、性能预算和可观察性；未进入施工的项目不预设实现细节。
