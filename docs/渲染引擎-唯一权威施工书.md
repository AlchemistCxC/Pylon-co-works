## 0. 已锁定决策

1. **SolidJS 是 AgentSheet/聊天工作台唯一主实现。** 不再做 React/Solid 选型比较，也不以对照 benchmark 作为转正前置条件。
2. **React Workbench 只作故障降级。** React GUI 外壳、设置、侧栏和其他 Sheet 不在本项目迁移范围；React fallback 只承诺数据可见、交互可恢复，不追求所有富视觉与 Solid 完全同构。
3. **canonical event journal 是会话事实的唯一持久化权威。** Agent transcript 只能作为显式恢复输入，不能与 canonical journal 并列成为第二渲染真相。
4. **不另立中央。** 继续深化现有 `RendererRegistry`、`PresentationProfileRegistry`、`PluginSettingsStore` 与工具语义 registry；新增 module 只做适配、投影或纯解析，不复制权威状态。
5. **完全信任第三方插件代码。** 第三方可以贡献 Solid renderer；schema 校验用于可诊断性、设置生成和热重载一致性，不以安全沙箱为目标。
6. **所有渲染类型必须开放。** 每个内置或插件 namespaced render kind 都必须有：语义输入契约、Solid renderer 选择点、默认 fallback、表现 token schema、设置 UI 描述、插件注册接口和测试 fixture。
7. **归一化必须保留未知数据。** 已知内容进入强类型字段；未知 provider block/event 保留 raw，并通过通用 fallback 可见，禁止静默丢弃。

### 1.3 传输现实

- 标准 ACP 可稳定承载 text、thinking、image、tool lifecycle、tool content、diff、location、plan、usage。
- Hermes ACP 会把许多结构化工具结果格式化为 text/diff；丰富 delegation/media 语义并不都进入标准 ACP。
- Peri 已有 `peri/unstable-event` 承载预算、预测、交互、rewind、插件等扩展事件。
- claude-code-best ACP bridge 当前跳过 attachment、tool summary，subagent progress 只抽出 text；`parentToolUseId` 仅在 `_meta.claudeCode` 中保留。
- 因此采用三阶输入：**标准 ACP → provider 扩展 metadata/event → raw fallback**。缺失的 provider 扩展由对应 adapter 增量补充，不污染 core reducer。

## 2. 当前拓扑与根因

~~~mermaid
flowchart LR
  A[ACP SessionUpdate] --> B[chatEventController]
  B --> C[sessionRuntimeStore]
  C --> D[Message / streaming / plan / usage]
  D --> E[chatRowPipeline]
  E --> F[React ChatView]
  F --> G[MessageRendererHost]
  G --> H[RendererRegistry.renderMessage]
  D -. preview only .-> I[SolidWorkbenchApp]
  I --> J[Solid rows/tools/footer/plan/input]
~~~

根因不是单纯“缺几个组件”：

1. `Message` 同时承担 transcript、tool projection 和 render payload，承载不了活动图、交互队列、会话状态。
2. `WorkbenchRuntimeSnapshot` 只暴露消息、流式文本、简化 plan、tokenCount 与模型/模式子集。
3. `RendererRegistry` 的 message/content/tool 三类接口重叠且浅；`renderTool`、`renderReasoning` 没有生产消费点。
4. `ContentRendererKind` 封闭；部分 provider 只注册元数据，不返回 surface。
5. 工具 catalog 与 YAML overlay 是“整 provider 替换”，会删除未覆盖的内置工具；简单取消 unregister 又会留下旧 overlay 和 alias。
6. Solid 完整 Workbench 未进入 AgentSheet 生产分支；流式内容仍由 React 直渲染。
7. canonical replay、agent replay、live event 仍可能形成多路投影；渲染层不能再增加第四份状态。

| 数据 | 唯一权威 | 说明 |
|---|---|---|
| 会话事件 | canonical event journal | live 事件规范化并追加，再由同一 reducer 投影 |
| 运行时 UI | `WorkbenchDocument` | 可由 journal 重建，不另作业务持久化 |
| renderer 贡献 | `RendererRegistry` | kind 与 implementation 由 owner/scope/shadow transaction 管理 |
| 工具语义 | tool registry baseline + overlay 有效视图 | 组件不得猜 tool name |
| profile | `PresentationProfileRegistry` | 只保存表现 token |
| 用户表现覆盖 | 设置 store | 不写会话 journal |

Agent transcript 恢复必须是：

~~~text
canonical 可用 → 只 replay canonical

canonical 缺失/损坏
  → 显式读取 agent transcript
  → adapter 生成 recovery-import event
  → 追加 canonical journal
  → 从 canonical replay
~~~

禁止把 agent transcript 直接写 `WorkbenchDocument`；禁止 canonical/agent 两份直接择一。

### 4.2 canonical 包络

~~~ts
export interface WorkbenchEventEnvelope {
  readonly schemaVersion: 1
  readonly eventId: string
  readonly sessionId: string
  readonly sequence: number
  readonly recordedAt: string
  readonly occurredAt?: string
  readonly source: {
    readonly provider: 'peri' | 'hermes' | 'claude-code' | string
    readonly sourceId: string
    readonly agentId?: string
    readonly parentAgentId?: string
  }
  readonly identity: {
    readonly turnId?: string
    readonly messageId?: string
    readonly toolCallId?: string
    readonly taskId?: string
    readonly runId?: string
    readonly interactionId?: string
  }
  readonly origin: 'live' | 'recovery-import'
  readonly event: WorkbenchSemanticEvent
  readonly raw?: JsonValue

~~~

约束：

- `sequence` 是 session journal 顺序；provider sequence 只作 metadata。
- identity 缺失时生成稳定派生 id，不得以 reducer 当下时间或数组下标作为最终身份。
- `raw` 必须可 JSON 序列化，写 journal 前有大小上限和 truncation metadata。
- `schemaVersion` 迁移在 journal 读取 seam 完成；renderer 不认识历史 schema。

~~~ts

  | FileReferencePart | FileSelectionPart | DiffPart
  | TerminalPart | LogPart | ProgressPart | ListPart | KeyValuePart
~~~

字段要求：

- 媒体：source（url/path/base64/blob）、mimeType、alt、尺寸/时长、poster、transcript；大 payload 不复制进多个 projection。
- 文件：path/URI、line/column/range、selection、language、exists。
- diff：path、old/new 或 unified、hunks、stats、location。
- terminal/log：stdout/stderr、exitCode、truncated/omittedBytes、stream id。
- tool result：允许嵌套 `ContentPart[]`，保留 rawOutput 与 error。
- resource：ACP resource link、embedded text/blob 与 MCP resource 一等化。
- unknown：originalType、summary、raw、truncated；默认显示类型、摘要和可展开 JSON。

## 5. 开放渲染种类、字典与设置接口

### 5.1 一个 catalog，三种职责

深化现有 `RendererRegistry`，不创建并列 `RenderCenter`：

1. `registerRenderKind`：声明 semantic kind、fallback、settings schema、fixture。
2. `registerSolidRenderer`：声明可消费 kind，并返回 `RenderSurface`。
3. 兼容现有 message/content/tool/highlighter API；迁移完成后前三者 deprecated。

工具字典属于语义归一化，不是 renderer catalog。它把 provider tool name 映射 action/kind/capabilities；renderer 再按 semantic kind 选 surface。

### 5.2 核心接口

~~~ts
export type RenderKind = BuiltinRenderKind | `${string}.${string}`

export interface RenderKindDefinition {
  readonly kind: RenderKind
  readonly label: string
  readonly category: 'message' | 'content' | 'tool'
    | 'activity' | 'interaction' | 'session'
  readonly fallbackKind: RenderKind
  readonly defaultTokens: Readonly<Record<string, RenderTokenValue>>
  readonly settings: readonly RenderSettingField[]
  readonly fixture: RenderFixture
}

export interface SolidRendererDefinition
  extends RendererDefinitionBase<RenderNodeSnapshot> {
  readonly rendererId: string
  readonly kinds: readonly RenderKind[]
  createSurface(input: SolidSurfaceInput): RenderSurface<RenderNodeSnapshot>
}

export interface RenderSurface<TSnapshot> {
  readonly rendererId: string
  readonly framework: 'solid'
  mount(container: HTMLElement, snapshot: TSnapshot): RenderHandle
  update(handle: RenderHandle, snapshot: TSnapshot): void
  destroy(handle: RenderHandle): void
  on<T extends RenderSurfaceEvent>(
    event: T['type'],
    listener: (event: T) => void,
  ): () => void
}
~~~

`RenderNodeSnapshot` 必须是 semantic snapshot，不得传 React/Solid component。Solid update 更新 signals，不得 dispose 后整行 remount。

### 5.3 通用表现接口

每个 kind 自动继承：

| token | 类型 | 用途 |
|---|---|---|
| foreground、mutedForeground、background、borderColor、accentColor | color | 颜色 |
| fontFamily、fontSize、fontWeight、lineHeight | font/number | 字体 |
| iconSize、avatarSize、maxWidth、maxHeight、indentSize | length | 大小 |
| paddingInline、paddingBlock、gap、radius、borderWidth | length | 布局 |
| density | enum | 密度 |
| collapsedByDefault、showMetadata、showRaw | boolean | 行为 |
| animationDuration、opacity | number | 动效 |

kind 可增加 namespaced token，例如 `activity.subagent.treeLineColor`、`content.image.maxInlineWidth`、`interaction.approval.modalWidth`。

~~~ts
export type RenderSettingField =
  | { key: string; type: 'color'; label: string; default: string }
  | { key: string; type: 'number'; label: string; default: number;
      min?: number; max?: number; step?: number; unit?: string }
  | { key: string; type: 'boolean'; label: string; default: boolean }
  | { key: string; type: 'select'; label: string; default: string;
      options: readonly RenderSettingOption[] }
  | { key: string; type: 'text'; label: string; default: string;
      pattern?: string }
~~~

解析顺序：

~~~text
host safe defaults
  < render-kind defaults
  < active Presentation Profile kindTokens
  < user settings override
  < per-session preview override（不持久化）
~~~

`RenderAppearanceResolver` 是纯函数，不拥有 store。插件接口：

~~~ts
context.renderer.registerRenderKind({ ... })

  id: 'example.presentation',

~~~

host 从 `RenderKindDefinition.settings` 自动生成设置页；插件自定义页仍走 `context.settings`。renderer 只收已解析 appearance。

### 5.4 工具字典目标

~~~text
catalog baseline + provider runtime discovery + active YAML overlay
  = immutable effective provider dictionary
~~~

原子替换：

1. 为 provider 构造新 generation。
2. 拷贝 catalog baseline。
3. 合并 runtime discovery。
4. 应用 overlay upsert/remove/alias。
5. 在临时 Map 校验 alias target、重复 canonical name、action/kind、循环。
6. 一次 swap effective Map；旧 generation 与 alias 同时释放。
7. 只发布一次 revision。

不得使用“先 unregister provider 再逐项注册”的可见中间态。

## 6. Provider adapter 映射

### 6.1 Hermes

- ACP text/thought/tool/plan 走 `acpNormalizer`。
- `delegate_task` start/progress/result 映射 `activity.subagent`；保留 handle、parent、depth、role、provider/model、state、usage、tool summary、structured payload、error classification。
- async delegation 映射 `activity.background-task`，完成事件关联原 activity id。
- cost/files/tokens/hotness/maxDepth aggregate 由 selector 派生，不重复写 journal。
- todo cancelled 不能在 ACP 三状态 plan 中消失；用 metadata/tool raw 补全。
- image/vision/TTS/transcription/video 生成相应 media/document/text part；结构不足时 unknown fallback。
- approval/confirm/clarify 映射统一 interaction。

### 6.2 Peri

- 标准 ACP 与 `peri/unstable-event` 进入同一 adapter，按 identity 去重。
- v2 Render/State/Observe 分别进入可见语义、可恢复状态、诊断/遥测；Observe 默认不污染 timeline。
- Subagent、BackgroundTask、BgRegistry、WorkflowProgress 建 activity graph。
- compact/rewind/retry/stage/middleware/turn suspend 建 lifecycle/status。
- Hitl/AskUser/OAuth 建 interaction；Prediction/FileSuggestions 建 input assist。
- plugin snapshot/action/search 属插件管理 Sheet，不归 renderer registry，但复用 content kind。

### 6.3 claude-code-best

- Anthropic text/thinking/image/tool block 继续走标准 ACP。
- `parentToolUseId` 贯穿 identity，建立 subagent/tool parent link。
- AgentTool progress 不再只转发 text：provider extension 补 agentId、prompt、nested message、tool use/result、usage、status。
- Agent output completed/async_launched/remote_launched/teammate_spawned 映射 activity。
- 七类 TaskType 映射 background-task/workflow/process；killed 映射 cancelled。
- attachment 按 file/document/IDE、memory/skill/MCP、hook/system、plan/task/todo、usage/budget、team/mailbox、unknown 归组。
- grouped_tool_use/collapsed_read_search 是 presentation hint，原始 timeline 不删。
- redacted thinking 显示占位；compact/retry/budget/hooks/permission/AskUser 进入 lifecycle/interaction。

## 7. 施工分层与循环

- **架构层 A**：单一数据流、开放 registry、字典、Solid host、设置与插件接口。
- **内容层 C**：在架构接口上补齐可见类型；不得绕 registry 写死组件或在组件解析 provider raw。


## 12. 错误与自愈标准

~~~ts
interface RenderDiagnostic {
  code: string
  userMessage: string
  technicalMessage: string
  provider?: string
  sessionId?: string
  eventId?: string
  renderKind?: string
  rendererId?: string
  pluginId?: string
  recoverability: 'retry' | 'fallback' | 'reload-plugin' | 'reimport' | 'none'
  cause?: unknown
}
~~~

自愈顺序：

1. renderer 失败：同 kind 下一 implementation。
2. 全失败：kind fallback。
3. 自定义 fallback 失败：`content.unknown`。
4. Solid host fatal：保持同一 document，切 React generic fallback。
5. journal replay 失败：停止隐式混合，提供 recovery import。

fallback 必须留下诊断，不能“有画面即成功”。

## 13. 验收定义

### 架构层

- Solid Workbench 是 AgentSheet 默认生产路径；React 仅故障降级。
- canonical journal 唯一 durable authority；live/replay/recovery-import 深等。
- provider 判断只在 normalizer/tool dictionary。
- document 覆盖 timeline/activity/interaction/session。
- registry 支持开放 kind、Solid renderer、hot swap、fallback。
- 每个 kind 可在设置改颜色、大小等 token，插件可贡献专属 schema。
- tool partial overlay 不删除 baseline，reload 原子。

### 内容层

- C00–C15 均有 fixture、Solid、React generic fallback、settings、plugin override、unknown/error tests。
- 三 Agent source inventory 无静默 skip。
- 子代理可见 parent/depth/status/model/usage/tools/files/output/error，并有 capability-gated commands。
- image/audio/video/document/resource/diff/terminal 可见且不重复大 payload。
- approval/questions/OAuth/secret/sudo 有统一生命周期。
- retry/compact/rewind/budget/recovery 有可解释错误和恢复动作。

### 非目标

- 不重写 React GUI 外壳和其他 Sheet。
- 不为 React fallback 实现全部富 renderer。
- profile 不决定 Agent 业务或 renderer framework。
- registry 不保存会话、设置值、transport 状态。
- 不给第三方 renderer 建安全沙箱。
