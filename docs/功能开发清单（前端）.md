## 3. 已确认的前端状态不变量

### 3.1 三层 Session ID

1. `Session.id`：Zustand 本地实体 ID，消息缓存 owner 使用 `pylon-msgs-<id>`。
2. `Session.source`：Pylon/Tauri 路由 key，所有 command/event 的会话作用域使用它。
3. `Session.periId`：Peri ACP 远端 `sessionId`，只用于 ACP 远端会话相关调用。

禁止把 `Session.id` 当作 `source` 传给 Workspace、Logs、Chat 事件或后端 command。

### 3.2 异步所有权

- Chat 事件按 `source` 路由。
- 历史加载使用 load generation，旧 `session/load` 结果不能覆盖当前会话。
- 删除 session 必须清理本地消息缓存、source runtime、generating 状态、取消状态。
- Agent 切换/重连后旧 ACP generation 的事件不得写入新客户端状态。

### 3.3 状态和持久化

- Session/profile 通过 Zustand 与 `sessionPersistence.ts` / `profilePersistence.ts` 归一化。
- 主题字段由 `ThemeSettings`、`ZONE_FIELDS`、preset 和 migration 共同约束。
- 自定义 preset 只能保存主题字段，不能污染 sessions、profiles、runtime stats。
- Pet position/cache 使用独立 localStorage；不能把宠物运行状态误写成主题状态。

## 6. 修改完成定义

一个前端功能只有同时满足以下条件，才可从“待开发/待验收”改为“已验证”：

1. 当前源码存在完整入口到消费链路。
2. 有对应纯函数/结构回归测试，且测试不是 runner 允许失败项。
3. `npm run build` exit code 为 0。
4. 涉及 Tauri/ACP 的功能有真实 command payload、事件顺序、错误路径证据。
5. 文档记录具体路径、命令、exit code 和未执行项。
