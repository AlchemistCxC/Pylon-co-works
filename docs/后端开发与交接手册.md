# 第 1 章：准则、状态模型、编号、提交和检查节点

## 1.1 后端开发准则

1. **源码优先**：Pylon 当前 Rust 源码、Peri 当前 ACP handler/schema、Prism 当前 route/handler 是事实源；旧文档和 skill 只用于定位。
2. **后端边界**：后端 coder 只修改 `src-tauri/**`、必要 fixture/测试、`agents.yaml` 和本文；不修改 `src/**`，不修改 `F:\A-I\Agent\Peri`，不修改 Hermes 配置。
3. **保留混合工作区**：不执行 `git reset`、`git clean`、`git restore`、`git add .`、`git add -A`，不覆盖其他 coder 的 staged、unstaged 或 untracked 文件。
4. **Peri 是 ACP 真值**：method、params、notification、replay 顺序、stopReason、capability 以 Peri 当前实现为准。
5. **Prism 是 HTTP 真值**：method、path、query、body、响应和认证以 `G:\Project\prism` 当前源码为准；Pylon 不暴露任意 URL/HTTP 代理。
6. **安全优先**：generation 隔离、pending 收敛、child kill/wait、路径 containment、Git 参数固定、loopback 和 secret 脱敏优先于便利性。
7. **不制造伪可用能力**：DTO、command 注册、pure helper、mock server 或 fake ACP 只能证明对应层，不得写成真实 Tauri/Peri/Prism 完成。
8. **最小切片**：按一个可观察用户结果或一个独立根因拆任务；避免“完善系统”“继续优化”这类不可验收标题。
9. **文档与源码同步**：任何源码、测试、配置或本文修改后，旧验证证据均视为 stale；最终只引用最后一次写操作后的验证。
10. **后端不拥有 Sheet 布局**：Sheet 顺序、active Sheet、关闭历史和视觉状态由前端持有；后端只提供 Agent、Session、Workspace、Runtime、Prism 等数据能力。

## 1.2 ID 和作用域不变量

```text
sheetId              前端 Workspace Sheet 实体
agentId              Agent registry key
Session.id           前端本地实体 ID
source               Pylon/Tauri Session 路由 key
periId               ACP 远端 sessionId
sessionGeneration    本地 Session 映射代际
clientGeneration     当前 ACP client 代际
```

强制规则：

- `Session.id`、`source`、`periId` 不能互换。
- Workspace/Git root 必须由 `source → SessionInfo.cwd` 解析，前端不得传任意绝对 root。
- `session/update` 只有远端 `sessionId` 时，必须用当前 generation 的 `periId → source` 唯一映射恢复 source。
- 无匹配或多匹配时丢弃通知并记录安全诊断；不得“取第一个”。
- 所有异步 mutation/cleanup 在 `.await` 后、修改本地状态前重新验证 `source + periId + sessionGeneration + clientGeneration`。
- destructive cleanup 统一使用 `remove_session_if_matches`，不得复制内联 `HashMap::remove` 条件。

## 1.3 当前架构事实

当前是单 active runtime，不是多 Agent 并行：

```text
AppState
├─ acp                 一个全局 AcpClient
├─ active_agent        一个当前 Agent
├─ client_generation   一个全局 client generation
├─ sessions            source → SessionInfo
├─ notification_task   一个长期 dispatcher
├─ runtime_logs        脱敏 ring buffer + broadcast
├─ runtime_mcp         进程内 MCP snapshot
├─ prism               固定 loopback PrismClient
└─ pet                 单一 PetState
```

Agent 替换当前路径：

```text
spawn + initialize 新 ACP
→ 提交区内替换旧 client
→ generation + 1
→ 更新 active_agent
→ sessions 处理（keep_sessions 参数）：
   手动 switch/reconnect → 清空映射（跨 agent/全新进程语义）
   自动重连             → 保留映射 + 迁移 generation（崩溃前会话可续聊）
→ 重启 dispatcher
→ kill + wait 旧 child
```

`auto_reconnect_active` 标志防 dispatcher 多次崩溃通知重复调度自动重连。

因此当前产品契约只能表述为：多个 Agent Sheet 可以保存不同工作现场，但同一时刻只有一个 active runtime Agent。真正后台并行由 B7 负责，当前不能宣传为已支持。

完成代码后按变更范围执行，不机械跑全套：

```bash

git diff --check -- src-tauri docs/后端开发与交接手册.md
```

证据解释：

- `cargo check`：只证明源码编译。
- `cargo test --lib --no-run`：只证明 test executable 生成。
- `cargo test --lib ...`：只有进程实际启动并返回测试结果，才证明 harness 执行。
- focused fake ACP：只证明 fake child 覆盖范围，不证明真实 Peri。
- `npm run build`：前端 TypeScript/Vite build，不证明 Tauri invoke 或真实后端。
- `git diff --check`：只证明 whitespace，不证明功能。

Windows GNU executable 启动错误（例如 `0xc0000139 / STATUS_ENTRYPOINT_NOT_FOUND`）必须标记为 harness 启动阻塞，不能写成测试通过，也不能把 `--no-run` 升级为 harness 证据。

业务结果：Agent 配置来源可预测；坏 Agent 或 Prism 不会让主窗口无法打开；前端拿到稳定的 Agent ID、名称和状态。

当前源码事实：

- `agent_config::load()` 现在优先读取 `PYLON_AGENTS_CONFIG`，未设置时读取内置 `agents.yaml`；reload 仍需显式 path 或环境变量。

## B1：ACP Session 生命周期、事件隔离与真实 Peri 主链

业务结果：new/send/cancel/close/load/switch/reconnect 在并发、EOF、超时和旧 response 迟到时不串状态、不误删新 Session、不遗留 child。

当前已有：

- `acp.rs` 有 pending shard、stdout EOF drain、crashed 快速失败、cancel settle、session/load replay boundary、ManagedChild kill/wait。
- fake ACP 已覆盖 initialize/new/prompt、EOF、cancel/close wire、malformed JSON、stderr、延迟 response 和目标 Session replay 隔离。
- `agent_runtime.rs` 有 `notification_is_current`、`session_mapping_matches`、`source_for_peri_id_in_generation`。
- `lib.rs` 有两阶段 Agent replacement、`remove_session_if_matches`、load rollback。

### B1.1 补齐异步 mutation 身份重验

重点检查 `set_mode`、`set_config_option`、prompt success/error/timeout、close、load success/rollback。所有 `.await` 后的本地 mutation 必须同时验证 source、periId、Session generation 和 active client generation。

当前已知风险：

- `send_message` 首次 prompt 成功后仍按 source 找 Session 修改 `has_first_prompt`，需统一 expected mapping 检查。
- `set_mode`/`set_config_option` mismatch 时可能只静默不更新，需稳定 stale/error 语义。
- `replace_agent_client` 已支持 `keep_sessions` 参数（手动清空 / 自动重连保留 + generation 迁移），"清运行态"与"清本地 Session 映射"的语义已冻结在调用点。

### B1.2 稳定错误 DTO

当前 `PylonError` 的 `Serialize` 仍输出纯字符串，command 也大量返回 `Result<_, String>`。先覆盖 Session/Agent 主链：

```json
{
  "code": "session_not_found",
  "message": "可读错误",
  "retryable": false,
  "details": {}
}
```

不要求一次性重写全部错误，但前端必须能区分 not found、closed、timeout、stale、crashed、configuration error。

### B1.3 dispatcher event-level 隔离

用可控 fake ACP 覆盖：A→B→A 替换、旧 notification/response 迟到、同 periId 多 source、旧 generation 错误路径。断言：

- 旧 event 不更新新 Session。
- 旧错误不删除新 mapping。
- `peri:update` 携带正确 source。
- pending 每个 waiter 只结算一次。
- dispatcher 重启后不会重复消费或丢失新事件。

### B1.4 session/load replay 高层边界

以 Peri 源码校对 replay-before-response，以及 load 后 config/available commands update。覆盖大历史、交错其他 Session、空 replay、config update 和 response boundary。

### B1.5 真实 Tauri + Peri 主链

真实验收顺序：

```text
启动 → initialize → new → prompt/update/done
→ set mode/model → cancel → list/load replay
→ close → switch/reconnect → 关闭窗口
```

证据必须包含 WebView invoke/event、Peri stdio JSONL、错误路径和 Windows PID/进程树。fake ACP、cargo test 和浏览器 invoke 错误不能替代真实证据。

出口：CP-B1 只承诺单 active Agent 主链，不承诺多 Agent 并行。

## B2：Workspace、Inspector、Activity 与 Runtime

业务结果：右栏当前真实调用得到稳定数据；不同 source 不串 Workspace/Runtime；大文件和日志可安全分页/导出。

当前已有：

- `runtime_log.rs` 有 ring buffer、过滤、broadcast 和递归脱敏。
- command 已注册 `get_workspace_root`、`list_workspace_entries`、`read_workspace_text`、`list_runtime_logs`、`clear_runtime_logs`。

### B2.1 Inspector 聚合 snapshot

已实现 v1：`session_inspector`（无参全局聚合）返回 agent 状态 + summary（sessionCount/activeCount/tokens 聚合）+ sessions 明细；`activeCount` 为 `has_first_prompt` 会话数（保守近似，`last_activity_at` 留档）。

完整版（增量）：`get_session_inspector { source }`——Agent、status、generation、Session 标题/mode/model/token/context、Workspace、Runtime warning/error count、capability flags。子项失败返回 partial status，不因一个子系统失败丢失整份 snapshot。

### B2.2 Workspace 分页和版本对账

## B9：权限审批流（tool-call 批准与 session/request_permission）

业务结果：agent 工具调用按前端权限模式（bypass / auto / edit / default）放行、自动或询问用户；不悬挂 pending；前端可显式批准/拒绝并记忆选择。

当前源码事实：

- 前端已有权限模式 UI，后端只把模式透传为 `edit_approval_policy` 配置；**批准交互流完全空缺**——dispatcher 收到 tool_call 通知后只转发 + 喂宠物，无挂起、无响应。
- 官方 schema（agent-client-protocol-schema 1.4）已有批准类型：`session/request_permission`（v1+v2，x-side=client——GUI 是调用方）、`RequestPermissionRequest { sessionId, prompt, subject, options }`、`PermissionOption`（AllowOnce / AllowAlways / RejectOnce / RejectAlways）、`RequestPermissionResponse { outcome }`。
- **方向语义待 wire 实测**：request_permission 由 GUI 主动调用询问 agent，还是 agent 在 tool_call 通知后挂起等 GUI 授权——需要 fake + 真实 Peri/Hermes 确认。

### B9.1 批准方向 wire 实测

用 fake ACP 和真实 Peri/Hermes 确认：工具调用前 agent 的挂起行为、request_permission 的调用方向、outcome 的语义（谁返回）、AllowOnce/Always 的持久化位置。产出批准流时序图。

### B9.2 挂起与恢复

dispatcher 识别需要批准的 tool_call → 挂起该 prompt 的通知流转（不提前 emit 完成）→ 收到用户决定后继续/中止；超时策略（默认拒绝并报告，不悬挂）。

### B9.3 模式判定

bypass = 自动放行；auto = 自动按规则；edit = 前端弹窗 + 等待用户选择；default = agent 默认策略。判定结果落日志（不含 secret/原始 prompt）。

### B9.4 前端契约

新命令（如 `approve_tool_call { source, requestId, option }`）+ 新事件（`pylon:permission-request`，含安全字段：toolName、提示语、options；不含 raw prompt/参数 secret）。契约同步到第 4.2 节。

### B9.5 集成测试

fake ACP 批准流：tool_call → 挂起 → 前端响应 → prompt 继续；拒绝路径不悬挂；超时路径报告。真实 Peri wire 验收留 CP-B9。

非目标：不实现 fs/network 工具面；不实现权限 UI 本体（前端）。

出口：CP-B9 要求真实 Tauri 弹窗 + 真实 Peri/Hermes 批准 wire 证据。
