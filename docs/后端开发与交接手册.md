## 2. 源码地图

### 2.1 `lib.rs` — 主状态机 + Tauri 命令（~2,300 行）

| 区域 | 内容 |
|:--|:--|
| `AppState` | 17 字段全 Arc：acp / notification_task / session_creation / agent_lifecycle / client_generation / prompt_locks / agents / active_agent / sessions / pet / runtime_logs / runtime_mcp / agent_runtime / auto_reconnect_active / prism |
| `AppStateHandles` | AppState 字段子集（11 字段），供 async 闭包/静态辅助持有（Tauri state 不能 move） |
| 通知 dispatcher | `start_notification_dispatcher`：broadcast 订阅 → generation 路由 → session/update 变体处理 → 崩溃检测 + 自动重连调度 |
| 连接路径 | `do_connect_and_replace`（静态辅助，手动/自动共用）→ `replace_agent_client`（keep_sessions 参数） |
| 命令区 | Session/Prompt、Agent、Workspace/Runtime/MCP/Pet、Prism 四组（全表见 §4） |
| 运行入口 | `run()`：manage → invoke_handler → setup（宠物加载）→ App::run（Exit 兜底持久化） |

关键不变量：客户端替换时 `client_generation` +1；dispatcher 与 session 映射按代际匹配；mutation 在 `.await` 后重验 mapping。

### 2.2 `acp.rs` — ACP 客户端（1,443 行）

- **方法常量**：9 个官方（initialize/new/prompt/close/load/list/set_mode/set_config_option/cancel）+ 1 个 Hermes 扩展（`session/set_model`，官方 schema 1.4 无此类型）
- **参数构造**：`session_*_params` 函数用官方 schema 类型序列化（`to_params`），MCP 走 `mcp::validate_and_serialize`
- **AcpClient**：`ManagedChild`（spawn + stdin/stdout/stderr）+ `write_tx`（mpsc 写通道）+ `next_id` + `pending`（16 分片 HashMap）+ `rx`（broadcast 256）+ `crashed`（AtomicBool）
- **锁外 RPC 模式**：`prepare_rpc` 同步产出 `PreparedRpc { id, line, write_tx, rx, pending }` → 发送/等待在锁外 → Peri 卡顿不阻塞其他命令
- **超时**：PROMPT_TIMEOUT 300s、CANCEL_SETTLE 30s、附件 10MB×8
- **reader**：stdout EOF → 广播 `pylon:agent-crashed` + drain pending（`ACP connection closed`）
- **child 清理**：`kill_and_wait` 三态（已退出/kill+wait/try_wait 失败兜底）；`Drop` 也 kill——任何错误路径不遗留子进程
- **fake 测试基建**：python 子进程脚本（`FAKE_SCRIPT` 模式：crash/alive），覆盖 initialize/new/prompt/EOF/cancel/load replay/malformed/stderr/延迟

### 2.3 `agent_runtime.rs` — 生命周期与路由纯逻辑（163 行）

- `AgentLifecycleStatus`：connecting/connected/reconnecting/crashed/disconnected/error
- `AgentRuntimeState`：status + last_error + last_connected_at
- 纯函数：`session_mapping_matches`、`source_for_peri_id_in_generation`（同代际唯一解析，多匹配拒绝）、`status_after_connection_failure`
- 自动重连常量：`MAX_RECONNECT_ATTEMPTS=5`、`reconnect_backoff_ms`（2^attempt 封顶 30s）

### 2.4 `agent_config.rs` — agents.yaml 解析

- `PYLON_AGENTS_CONFIG` 优先，否则内置 `agents.yaml`；`load_from_path` 支持显式路径
- `default_agent_id`：多个 default 拒绝；无 default 按 ID 字典序确定性回退
- `AgentDef`：name/transport/exe/args/cwd/env/default；env 含 secret 不进任何输出

### 2.5 `mcp.rs` — MCP 配置校验/序列化

- `McpServerConfig`：transport（stdio/sse/streamable-http/http）/URL/args/env/headers/OAuth/enabled
- 上限：MAX_SERVERS 32、args/env/headers 各 64
- `validate_and_serialize` → 官方 schema `SetSessionMcpServersRequest` 类型；secret 进 wire 不进日志

### 2.6 `prism.rs` — Prism loopback 客户端

- `PrismClient`：固定 loopback（默认 `http://127.0.0.1:9337`，`validate_loopback_url` 白名单）、GET/POST/PUT/DELETE、query、Bearer（PRISM_ADMIN_API_TOKEN）、非 2xx 截断 4096、`unavailable` 降级
- status 分类：connected/unavailable/unauthorized/configuration_error/error

### 2.7 `runtime_log.rs` — 运行时日志中心

- ring buffer 2000 条 + broadcast 256 + 过滤查询 + 递归脱敏（rawInput/rawOutput/prompt/persona/headers/env/authorization/token/secret）
- 消息截断 8KB

### 2.8 `workspace.rs` — 工作区只读接口

- root 由 `source → SessionInfo.cwd` 解析；`resolve_workspace_path` canonical containment（穿越/前缀/UTF-8/NUL 检查）
- 目录上限 1000 条；预览默认 256KB / 最大 1MB

### 2.9 `error.rs` — PylonError

- 枚举：Acp/SessionNotFound/NoActiveAgent/Workspace 等；当前 `Serialize` 仍是纯字符串（B1.2 目标结构化 DTO）

### 2.10 `pet.rs` + `pet-core/` — 宠物

- `pet-core` 独立 crate（366+ 行）：事件驱动状态机，5 阶段（XP 0/25/90/220/500）、7 情绪、记忆 10 条（里程碑：首任务/每10次/进化/7天）、睡眠（首字 30s 无互动入睡、访问唤醒）、TokenDelta 预留
- `pet.rs` 适配层：事件转接 + `PetView` DTO + 落盘持久化（`save_to_file` 原子写 / `load_from_file` 容错读）
- 落盘：`app_config_dir/pylon-pet.json`；写时机 get_pet（12s 轮询）+ pet_action + RunEvent::Exit

### 2.11 `main.rs` — 入口

`run()` 调用 lib；Tauri context 在 build.rs 注入 comctl32 v6 manifest（windres .o，测试 exe 兼容）。

## 5. 关键机制

### 5.1 generation 路由与 session 映射

```
source ── SessionInfo { peri_id, generation, ... } ── 映射
client_generation = 客户端替换计数（每次替换 +1）
dispatcher 持 generation 快照；session/update 按 (peri_id, generation) 唯一解析 source
```

- 旧代际事件：`session_mapping_matches` / `source_for_peri_id_in_generation` 拒绝（log warn，不取第一个）
- 客户端替换后旧 session 映射若迁移 generation 仍有效（自动重连续聊），否则前端按错误清理

### 5.2 崩溃自动重连

```
stdout EOF → pylon:agent-crashed → dispatcher 置 Crashed + emit
→ auto_reconnect_active.swap(true) 防重入
→ 闭包循环 5 次：sleep(2^attempt s 封顶 30s)
   → 复查 status==Crashed（用户手动 reconnect 则放弃）
   → 复查 generation 未变
   → do_connect_and_replace(Reconnecting, keep_sessions=true)
→ 成功 break / 全败 Release 标志 + log error
```

### 5.3 锁外 RPC（V14 模式）

所有 RPC（new/prompt/set_mode/set_config_option/cancel/close/load）统一：短锁内 `prepare_rpc`（同步准备）→ 锁外发送 + 等待。Peri 卡顿时其他命令不阻塞。响应通过 `AcpClient::complete_rpc` 或 `PromptWaitOutcome` 结算。

### 5.4 child 生命周期

- spawn 后 stdin/stdout/stderr 全部接管；stdout reader 线程广播消息
- 退出清理：`kill_and_wait`（已退出直接返回；否则 kill + wait；try_wait 失败兜底继续 kill）
- `Drop` 也清理——AppState 销毁链自动收尾，无孤儿进程
- 附件：10MB × 8 上限；`infer` 类型探测

### 5.5 宠物（事件源与持久化）

事件源：聊天（发送/首字/完成/失败/token 全量/工具三态）· 互动（poke/feed/rename/每日访问）· `get_pet` 轮询自动入睡 · Agent 连接成功/崩溃。落盘：`app_config_dir/pylon-pet.json` 原子写；写时机 get_pet + pet_action + Exit；启动加载容错（缺失/损坏→新宠物）。

## 6.1 待开发任务详章（B9-B11）

### B9 权限审批流（tool-call 批准 + session/request_permission）

业务结果：agent 工具调用按前端权限模式（bypass / auto / edit / default）放行、自动或询问用户；不悬挂 pending；前端可显式批准/拒绝并记忆选择。

当前源码事实：

- 前端已有权限模式 UI，后端只把模式透传为 `edit_approval_policy` 配置；**批准交互流完全空缺**——dispatcher 收到 tool_call 通知后只转发 + 喂宠物，无挂起、无响应。
- 官方 schema（agent-client-protocol-schema 1.4）已有批准类型：`session/request_permission`（v1+v2，x-side=client——GUI 是调用方）、`RequestPermissionRequest { sessionId, prompt, subject, options }`、`PermissionOption`（AllowOnce / AllowAlways / RejectOnce / RejectAlways）、`RequestPermissionResponse { outcome }`。
- **方向语义待 wire 实测**：request_permission 由 GUI 主动调用询问 agent，还是 agent 在 tool_call 通知后挂起等 GUI 授权——需要 fake + 真实 Peri/Hermes 确认。

B9.1 批准方向 wire 实测 → B9.2 挂起与恢复（tool_call 挂起 → 用户决定 → 继续/中止；超时默认拒绝）→ B9.3 模式判定（bypass/auto/edit/default）→ B9.4 前端契约（`approve_tool_call` 命令 + `pylon:permission-request` 事件，安全字段不含 secret）→ B9.5 集成测试（fake 批准流；拒绝/超时不悬挂）。

非目标：不实现 fs/network 工具面；不实现权限 UI 本体（前端）。出口：CP-B9 真实 Tauri 弹窗 + 真实 Peri/Hermes 批准 wire。

### B10 平台适配器层（Gateway）

业务结果：Pylon 从"桌面 GUI"扩展为"消息网关"——平台消息（QQ 等）经适配器直连接入，与本地 GUI 消息走同一 agent 管线和注入管线；Prism 保持本地服务（上下文注入插件），不做平台桥接。

```text
QQ开放平台 ──WS直连── Gateway(Pylon) ──ACP── Agent
                         │
                         ├─ gateway/mod.rs  PlatformAdapter trait + 注册表
                         ├─ gateway/qq.rs   QQ 适配器（WS/事件/发送，移植自 Prism qq 模块逻辑）
                         │
Prism(9337) ──HTTP loopback── 注入插件（/inject 提供 context，现状通道）
```

信息脉络：`agent ←ACP→ Pylon(gateway) → 平台`；Prism 是附加插件（上下文注入），不承担平台桥接（其 qq 模块闲置）。

当前源码事实：

- 前端 Session 已有 `platform` 字段（'local'/'qq'），source 是字符串路由 key，可扩展 `qq:group:{id}` / `qq:user:{openId}`。
- 后端无平台适配器抽象；消息只来自 GUI 输入（send_message）；agent 事件只发 WebView（无平台投递通道）。
- Prism 的 qq 模块（ws.rs/types.rs/events.rs/send.rs/auth.rs）可作移植参考：QQ 开放平台 WS gateway + 事件解析 + v2 API 发送。
- QQ 凭据：app_id + client_secret（Prism 里经 /qq/connect 传入；Pylon 改为配置 `PYLON_QQ_APP_ID` / `PYLON_QQ_CLIENT_SECRET` 或 gateway 配置段）。

B10.1 PlatformAdapter trait + gateway 框架（ingest/deliver + 注册表；事件广播改造：peri:update/done/error 从"只发 WebView"改为"广播到 WebView + 各平台适配器"）→ B10.2 QQ 适配器移植（WS 连接/事件解析/发送；凭据配置化；Prism 零改动）→ B10.3 source 映射 + 平台会话生命周期（首次消息自动建 agent session、复用、超时策略）→ B10.4 集成测试（fake QQ 事件流 → ingest → 注入钩子 → fake ACP → deliver 回发）。

非目标：不把 Prism 代码嵌入 Pylon；不做微信/飞书适配器（trait 留扩展位）。出口：CP-B10 真实 QQ 机器人 wire（或用户授权跳过）。

### B11 注入钩子（gateway 消息管线）

业务结果：本地 GUI 与平台适配器消息统一走"发送前置注入"——调 Prism `/inject` 拿 context，拼进 prompt 后经 ACP 发给 agent；生成后持久化可配置（也可能不持久化）。

```text
用户消息（GUI / QQ 适配器）
  → 注入钩子: /inject { scenario, sources, user_msg, round } → context + activated
  → prompt 组装: [注入 context] + 用户消息 → ACP session/prompt → agent → LLM
  → 完成（可选）: 持久化开关（Pylon session 持久化 / Prism chronicle / 跳过）
```

当前源码事实：

- Prism `/inject`（POST）：请求 `{ scenario, sources, user_msg, round }`，响应 `{ context, activated, source }`——**user_msg 即消息内容**，gate 引擎（世界书匹配：谓词 + 轮次）实时匹配返回注入文本。
- Prism 是"注入内容提供者"，不截获；截获逻辑在调用方（Pylon gateway）。
- `prism_inject` 命令已注册（HTTP 透传），但 send_message 未接注入钩子。

B11.1 发送前置注入钩子 + round 管理（send_message 与 B10 ingest 统一入口；round 每 session 计数；context 拼进 prompt 文本块；activated 可选透传前端）→ B11.2 持久化开关 → B11.3 集成测试（注入桩 → prompt 组装断言 → fake ACP 回归）。

非目标：不实现 system/persona 级注入（第一版 prompt 前置注入）；不改 Prism。出口：CP-B11 真实 Prism 数据目录注入验收（G:\Prism 临时 root）。

## 7. 开发流程

### 7.1 铁律

1. 源码优先：Pylon Rust、Peri handler、Prism route 是事实源；旧文档/skill 只定位
2. 后端边界：只动 `src-tauri/**`、fixture/测试、`agents.yaml`、本文
3. 保留混合工作区：不 reset/clean/restore/add .；不覆盖他人 staged/unstaged/untracked
4. 安全优先：generation 隔离、pending 收敛、child kill/wait、路径 containment、loopback、secret 脱敏
5. 不制造伪可用能力：DTO/command 注册/mock 不得写成真实链路完成
6. 一条一 commit：一个可验收切片一个 commit；cargo check 通过再 commit；不提前 build、不跳级
7. 文档与源码同步：修改后旧验证证据视为 stale

### 7.3 接管顺序

1. 刷新 Git 状态/branch/最近 commit/限定 diff
2. 对照 §6 确认目标大任务状态未被工作区改动改变
3. 读任务所需 Pylon 源码；协议任务同时读 Peri/Prism 真值
4. 记录外部改动归属，不覆盖、不 reset、不全量 stage
5. 选最高优先级未阻塞任务；"继续"时直接进入，不重复询问
6. 完成适用验证 → 更新本文 §6 → 一条一 commit → 停下汇报
