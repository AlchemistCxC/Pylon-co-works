# Pylon AgentSheet：经典终端的整体审美方向

> 视觉观察记录 · 2026-08-29  
> 观察范围：浏览器预览中的 `terminal-like / terminal-classic`，包括浅色、深色、空态、长消息、工具展开、失败工具、输入台、左栏折叠和消息流设置。  
> 现代 GUI 与其他 Sheet 不纳入本方案。

## 一句话结论

Pylon 不应该把自己做成“终端的复刻”，而应该成为一件**安静、精确、带有记录感的工作仪器**：像一页暖纸色的现场记录，Agent 的行动正在上面留下痕迹。

它需要保留终端的气质——即时、克制、可追踪、重视文本——但不必继承终端的外形崇拜：不需要黑底、满屏等宽字、每行一个命令，也不需要把所有内容压成字符画。

## 1. 目前界面的整体印象

现在的经典 AgentSheet 里，其实已经有一套很好的材料：暖灰纸张、朱砂色强调、苔绿色成功状态、`❯` 提示符、细竖线、低调的 Chevron 和 Pylon 标记。这些元素放在一起时，已经接近一种有性格的“工作现场”。

问题不在于缺少颜色或组件，而在于**空间没有一个绝对主角**：

- 顶部像浏览器标签栏；
- 左栏像 IDE 的资源管理器；
- 中间像终端记录流；
- 右栏像常驻的调试面板；
- 设置页又像一套主题编辑器。

它们各自成立，却没有被同一个视觉命题统领。于是第一眼更像“功能很多的开发工具”，而不是一件值得长时间使用的产品。

经典模式的另一个明显问题是：消息正文通常只占中间区域的一小条，右侧留下大块未经设计的空白；而顶部用户消息、工具行、输入台又各自使用不同的宽度。负空间本身没有错，但这里更像布局尚未决定，而不是有意留白。

浅色模式的问题是边线和控件略多，容易变成“表格化的设置系统”；深色模式的气质反而更集中，但思考文字、状态辅助文字和右栏的对比度太低。两种明暗不应该像两套产品，而应该像同一件仪器的白昼和夜间版本。

## 2. 设计命题：静默仪器 / Quiet Instrument

希望用户打开 Pylon 时感受到的不是“这里有很多按钮”，而是：

> 这里是一块正在发生工作的桌面。文字是正文，工具是边注，状态是标点，输入是页脚。

四个关键词：

| 关键词 | 视觉含义 |
| --- | --- |
| 安静 | 大面积平面、少量边线、没有持续发光和无意义的装饰 |
| 精确 | 固定阅读柱、统一基线、稳定的状态语法 |
| 温暖 | 纸张与朱砂，而不是冷蓝的默认开发者配色 |
| 活着 | 只有真正运行中的动作才有轻微动态，其余内容安静地退后 |

应当避免的感觉是：嘈杂、炫技、仪表盘、主题商店、终端 cosplay。

## 3. 预设系统应该分成两层：骨架不变，表达可变

目前的系统已经有 Interface Mode、Global Preset、Zone 设置、Presentation Profile 和 Renderer 设置等多层能力。这个方向是对的，但各层的职责必须更像“服装”和“身体”：

### 永远不应被预设改变的东西：产品骨架

- 顶部工作区轨道的位置和高度；
- 左侧索引、中央主舞台、右侧注释抽屉、底部命令台的关系；
- 主聊天的阅读宽度和对齐轴；
- 用户、助手、思考、工具、错误的语义顺序；
- 状态信息出现的位置和可发现方式；
- 输入区、停止、附件、模型等核心操作的相对位置；
- 折叠/展开后的信息层级。

### 可以被预设改变的东西：产品表达

- 色彩（纸张、墨色、强调色、状态色）；
- 字体组合（更技术、更编辑、更人文）；
- 边线的浓淡和虚实；
- 很窄范围内的圆角、密度和留白；
- 背景是否有极轻的纹理；
- 动效的强弱；
- 工具连接线是实线、虚线还是极淡的点线。

换句话说：**切换预设应该像换灯光和纸张，而不是搬动房间的墙。**

建议把现有能力理解成这样的关系：

```text
Interface Mode       决定语法：这是工作台还是记录流
Global Preset        决定材料：纸张、墨色、强调色、边线
Presentation Profile 决定气质：正文/工具/思考如何说话
Zone Settings        决定局部：某个区域的密度与细微偏好
Renderer Settings    决定例外：某种内容如何被精细呈现
```

其中只有第一层可以定义“语法”，后面几层都不应重新发明主布局。

## 4. 所有经典预设共用的 AgentSheet 排布

AgentSheet 应当固定成“一条主舞台、两个抽屉、一个命令台”：

```text
┌──────────────────── 顶部工作区轨道 ────────────────────┐
│  Pylon 标记   Agent / 会话标签             工具入口       │
├────── 索引抽屉 ────┬──────── 中央阅读舞台 ────────┬──────┤
│                    │                              │      │
│  工作区            │  用户请求                    │ 注释 │
│  会话              │  助手正文                    │ 抽屉 │
│  Agent             │  行动脊柱 / 工具链            │      │
│                    │                              │      │
├────────────────────┴──────────────────────────────┴──────┤
│                     底部命令台                            │
└───────────────────────────────────────────────────────────┘
```

### 中央阅读舞台

中央内容保持一条舒适的阅读柱，宽度稳定并居中。不要让每一条消息都无条件铺满整个主区，也不要让正文永远贴在左边、右边留下偶然的空洞。

用户请求可以有一条贯穿阅读柱的淡色底带；助手正文保持无框平面；工具详情沿同一条竖向轴缩进。这样负空间会变成“纸张”，而不是“没放东西的地方”。

### 行动脊柱

用户、思考、工具、结果都挂在一条细竖线上。它是 AgentSheet 最值得拥有的识别性元素。工具不应被看成一排互不相干的卡片，而应像一串连续动作：完成的动作变轻，当前动作留下朱砂色，错误动作留下短促的红色断点。

### 左侧索引抽屉

左栏负责“我在哪里”，不是负责展示所有 CRUD 操作。工作区和会话用列表关系表达，选中项用一条窄的朱砂色轨道和轻微底色表达。设置、导出、归档、删除等操作只在悬停或聚焦时出现，避免每个会话旁边常驻四个图标。

### 右侧注释抽屉

右栏只在有上下文时出现。空的右栏不应持续占据 260px 的视觉和空间预算；它打开时应像一本书的边注，而不是第二个主面板。

### 底部命令台

输入区是“写下一行”的地方，不是一个巨大的表单卡片。保留上下两条细线和左侧提示符是对的，但需要有很淡的输入提示、清晰的焦点表达，以及一行经过整理的上下文信息。模型、Profile、token、快捷键不应彼此挤成一串灰色小字。

## 5. 经典终端的表达方案

### 色彩

这套颜色值得继续发展，但要严格控制角色：

| 角色 | 建议方向 | 用途 |
| --- | --- | --- |
| 纸张 | `#F3F1EC` | 主画布、默认平面 |
| 墨色 | `#1C211E` | 正文、标题、主要操作 |
| 朱砂 | `#A94D35` | 用户标记、当前动作、链接、焦点 |
| 苔绿 | `#3D7655` | 成功、完成、健康状态 |
| 铅线 | `#B7B0A7` | 普通分隔线、次级边界 |
| 错误红 | 偏酒红而非亮红 | 错误断点和危险动作 |

经典预设里应清理残留的电蓝、紫色和霓虹高亮。颜色越少，朱砂色越像“编辑者的铅笔”，越有分量。

### 字体

不要让整页都说同一种话：

- 人写的内容、助手正文、标题：可读的系统无衬线或略有人文感的字体；
- Agent 的路径、代码、工具名、时间、状态：JetBrains Mono 等宽体；
- 微标签可以等宽并大写，但只作为边注，不要让它们统治页面。

这样仍然有终端的纪律，却不会像把所有自然语言强行塞进命令行。

### 表面、边线和圆角

- 经典模式以平面为主；
- 只有真正浮起的菜单、弹窗才使用阴影；
- 普通消息不做卡片；
- 线条要比现在更少、更软，重要边界才使用深线；
- 圆角保持 0–4px 的窄范围，避免胶囊和连续圆角；
- 不使用全局玻璃模糊来制造“高级感”。

### 动效

经典模式的动效应该像仪器的指示灯：

- 运行中的行有极轻的呼吸或光标感；
- 完成时只做一次短促的 settle；
- 普通思考、完成工具和静态正文不持续闪烁；
- 焦点用一条线或一小段色块表达，不用整块蓝色光环。

## 6. AgentSheet 各区域的目标画面

### 顶部轨道

保留 Agent/会话标签，但取消“每个标签都是一个盒子”的感觉。活动标签使用下划线或窄色条，关闭按钮仅在悬停时显现。左端应有一个稳定的 Pylon 识别点，而不是让彩色圆点成为主要品牌印象。

### 侧栏

侧栏应像目录页：工作区标题、路径、会话名和时间有明确的文字层级；空工作区退到安静的次级状态。`工作 / 聊天` 更适合做成文字导航加一条活动线，而不是厚重的分段按钮。

### 用户请求

这是目前最成功的视觉元素之一：淡色底带、左侧朱砂线、`❯` 前缀。保留这个语法，但把底带限制在阅读柱内，并让它成为整轮活动的开场标记。

### 助手正文

正文应当是页面上最有重量的内容。标题、段落、列表、表格和代码之间用留白形成秩序，不要再给每个内容块套一层表面。代码块可以保留左侧细线和非常淡的底色，重点是提高可读性，而不是增加装饰。

### Thought

思考是边注，不是第二篇正文。默认显示一行低对比度的 `Thought · 0s` 或本地化等价文字，展开时沿行动脊柱出现。它应该让人知道“这里发生过思考”，而不是抢走回答的注意力。

### Tool activity

工具链最好被感知成一个连续句子：`✓ Read → ✓ Grep → × Write`。完成行弱化，运行行突出，失败行只强调必要的错误信息。右侧 Chevron 在悬停/聚焦时出现即可，不要让每一行都带着同样重量的箭头。

### 空态

目前空态的 Logo、横向细线和中央构图很有潜力。需要改的是中间的表单：模型、权限、思考强度不应挤在一条原生控件横排里。空态应该像一张尚未写下第一行的纸：一句邀请、一个宽阔输入面、极少的上下文选择，以及一个明确的开始动作。

### 深色版本

深色的墨绿底 + 朱砂色其实很有魅力，应当保留同一套排布和语法，只把辅助文字抬高一点对比度，并把选中态的浅桃色收暗。深色不是“黑客主题”，而是同一间工作室的夜班灯光。

## 7. 先做什么，后做什么

### 第一阶段：先让人看到一个整体

1. 固定中央阅读柱和行动脊柱；
2. 让左右栏成为抽屉，空右栏不占主舞台；
3. 统一顶部轨道、正文和输入台的宽度关系；
4. 去除常驻的多余边框、卡片和操作图标。

### 第二阶段：让内容说不同的语言

1. 助手正文与机器信息分开字体；
2. 把完成/运行/错误收敛成同一套状态语法；
3. 统一思考、工具、代码的缩进和基线；
4. 重做空态和底部命令台。

### 第三阶段：让预设成为“换气质”而不是“换产品”

1. 以经典终端的纸张/朱砂/苔绿作为默认母题；
2. 把全局预设限制在颜色、表面、字体配对和动效强度；
3. 允许局部预设改变密度，但不改变主舞台几何；
4. 让每一个 Renderer 只负责自己的内容表达，不重新决定整个页面的布局。

## 8. 明确不要再做的事情

- 不要继续增加新的主题颜色来解决层级问题；
- 不要让每个消息、工具和状态都拥有自己的卡片；
- 不要用玻璃、模糊和阴影叠出“高级感”；
- 不要把所有操作按钮永久摆在会话列表上；
- 不要让空的右栏和空的状态区域持续占据注意力；
- 不要为了“终端感”把所有正文都改成等宽字体；
- 不要让切换预设同时搬动布局、改变信息顺序或改变基本交互位置。

## 9. 什么时候算是有品味了

在一张 1920px 的截图里，用户第一眼应该只看到一个主舞台，而不是一堆互相竞争的盒子；第二眼能分辨“我说的话、Agent 的回答、Agent 正在做的事”；第三眼才发现颜色、线条和字体的细节。

切换浅色/深色或不同全局预设时，房间的结构应该完全不变，只改变光线和材料。打开一个工具详情时，信息应该沿同一条脊柱自然展开，而不是突然弹出一张新卡片。没有会话时，空态应该仍然像同一个产品，而不是一张单独设计的表单页。

最终目标不是“看起来像终端”，而是让人相信：**这里的每一条线、每一个空白和每一个颜色，都在为工作让路。**
