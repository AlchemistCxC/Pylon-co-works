# Pylon 宠物状态机 v2 设计书（感知型桌宠）

> 状态：**设计稿 v0.1**（2026-08-01，待评审补充）
> 目标：把宠物从"事件→数值→文案"单向管道升级为"需求维度 × 层次状态 × 个性 × agent 活动感知"的复合状态机。
> 铁律：**零后台任务**——一切时间效果用时间戳结算（离线衰减/延迟行为/阶段性完成均正确）；前端零破坏（mood 保留、PetView 渐进扩展）。

---

## 1. 设计原则

| # | 原则 | 说明 |
|:--|:--|:--|
| 1 | 时间戳驱动，无后台任务 | 每次 `apply(event)`/`view()` 时按 `dt = now - last_tick_at` 结算衰减；离线 8 小时回来，宠物正确地饿了/委屈了 |
| 2 | 情绪推导而非直接赋值 | 事件只写入"最近事件窗口"；mood 由 `derive_mood(需求, 窗口事件, 个性, 时段)` 计算——杜绝"刚喂了食但还在生气"的错位 |
| 3 | 感知 agent，不感知细节 | 宠物只接收**脱敏摘要**（工具分类/文件名/模式），rawInput 原文绝不下沉（安全红线） |
| 4 | 渐进扩展，前端零破坏 | 旧存档 serde default 无损升级；mood 字符串保留；新字段可选消费 |
| 5 | 复杂状态机，简单接口 | 外部（Tauri 命令/前端）只看到 `apply(事件)` + `view()`，复杂度全在核心内部 |

## 3. 数据模型（PetState v2）

```rust
pub struct PetState {
    // ── 身份（保留）──
    pub name: String,
    pub born_at_ms: u64,
    pub stage: 阶段（由 xp 推导，保留 5 阶段）,
    pub xp: u32, pub bond: u32,

    // ── 需求维度（新增，0-100）──
    pub hunger: u8,        // 饱腹：醒着随时间降
    pub energy: u8,        // 精力：醒着降、睡眠恢复
    pub fun: u8,           // 娱乐：不互动降、玩耍/对话恢复
    pub loneliness: u8,    // 孤独：单独时间涨，互动清零

    // ── 个性（新增，出生随机/restore 保留，0-100）──
    pub traits: PetTraits, // activity / clinginess / greed / curiosity

    // ── 状态机（新增）──
    pub machine: PetMachineState,  // HSM 当前状态（见 §5）
    pub last_tick_at_ms: u64,      // 需求结算时间戳
    pub last_interaction_at_ms: u64,  // 已有（孤独/睡眠判定用）

    // ── 延迟行为（新增）──
    pub pending_action: Option<PendingAction>,  // crafting 等（时间戳完成）

    // ── 感知窗口（新增）──
    pub recent_events: VecDeque<RecentEvent>,   // 环形 8：情绪推导输入
    pub last_agent_mode: Option<String>,        // 最近工作模式
    pub last_agent_model: Option<String>,       // 最近模型

    // ── 统计（保留 + 新增）──
    pub stats: PetStats,  // 现有全部 + code_sessions/code_eaten/code_files 集合/friends_made/dazes

    // ── 记忆（保留机制，10 条）──
    pub memories: Vec<String>,

    // ── 瞬时（不落盘）──
    #[serde(skip)] pub msg: Option<String>,      // 待消费行为文案
    #[serde(skip)] pub last_interaction_at_ms: u64,
}

pub struct PetTraits { activity: u8, clinginess: u8, greed: u8, curiosity: u8 }
pub enum PetMachineState { Awake(MachineSub), Asleep }
pub enum MachineSub { Idle, Interacting, Distress }
```

## 4. 需求衰减引擎（时间戳结算）

每次 `apply(event)` 或 `view()` 前置结算：`dt = now - last_tick_at`（分钟，封顶 24h 防溢出）。

```
hunger     -= dt × 0.6  × (1 + greed×0.01)       // 贪吃饿得快
energy     -= dt × 0.5  × (1 - activity×0.005)   // 活跃耗能快（仅醒着）
fun        -= dt × 0.35
loneliness += dt × 0.25 × (1 + clinginess×0.01)
```

边界：全部 clamp 0-100；`last_tick_at_ms = now`。
睡眠时：energy 按 `+dt × 2` 恢复，其余需求暂停衰减（睡眠豁免）。
需求达 0 的惩罚：hunger=0 持续 → 每 tick 掉 bond 0.5；energy=0 持续 → 强制入睡（见 §5 转移表）。

## 5. 层次状态机（HSM）与转移表

```
PetMachineState
├── Awake
│   ├── Idle           默认
│   ├── Interacting    对话/互动进行中
│   └── Distress       agent 崩溃/错误风暴
└── Asleep
```

| # | 当前 | 条件 | 目标 | 进入动作 |
|:--|:--|:--|:--|:--|
| T1 | Awake.* | energy ≤ 15 且 30s 无互动 | Asleep | msg=打哈欠 |
| T2 | Asleep | 任何事件/访问 | Awake.Idle | energy +30 |
| T3 | Awake.* | AgentCrashed | Awake.Distress | — |
| T4 | Awake.Distress | AgentConnected | Awake.Idle | — |
| T5 | Awake.Idle | FirstChunk（对话开始） | Awake.Interacting | — |
| T6 | Awake.Interacting | PromptCompleted/Failed | Awake.Idle | 按结果给情绪 |
| T7 | Awake.Interacting | PromptTimeout | Awake.Idle | mood=dazed |
| T8 | Awake.* | energy=0 持续（见 §4） | Asleep | 强制入睡 |

转移由 `apply()` 驱动；`view()` 只结算需求与延迟行为，不主动转移（除 T1/T8 的睡眠检查——由 view 触发，与现有 check_sleepy 一致）。

## 6. 情绪系统（推导式）

### 情绪全集（mood 字符串，前端可消费）

```
idle curious excited happy focused error sleepy
hungry lonely tired dazed confused startled   ← 新增 6 个
```

### 推导优先级（derive_mood，自上而下取首个命中）

```
1. machine == Asleep                          → sleepy
2. 窗口事件含 AgentCrashed（近 3 条）          → error
3. hunger < 20                                → hungry
4. energy < 20                                → tired
5. loneliness > 60                            → lonely
6. 窗口事件含 PromptTimeout                    → dazed
7. 窗口事件含 refusal / tool cancelled        → confused / startled
8. 窗口事件含 喂食/玩耍/完成                   → happy
9. 窗口事件含 工具 started                     → focused
10. machine == Interacting                    → curious
11. 默认                                      → idle
```

新情绪行为语义：
- `dazed`：超时后短时（下次互动恢复），fun 微涨
- `confused`：refusal 后短时
- `startled`：工具被打断后短时（1 个事件周期）
- `hungry/lonely/tired`：需求驱动，喂食/互动/睡眠即消失

## 7. 个性系统（traits）

| trait | 影响 |
|:--|:--|
| activity 活跃 | 能量消耗率、互动欲望（fun 掉得快）、玩耍收益 |
| clinginess 黏人 | 孤独增速、被冷落时 bond 惩罚（孤独>80 持续 → bond -1/tick） |
| greed 贪吃 | 饥饿增速、喂食 bond 收益 ×(1+greed×0.01) |
| curiosity 好奇 | 新工具/新模式触发更强情绪（excited 概率）、阅读类活动收益 |

出生随机（可重 roll，restore 保留）；`rename`/`restore` 不清除。PetView 透出 traits 供前端展示"性格标签"。

| Read started | 歪头看 | mood=curious（低耗） |
| Execute started | 捂着耳朵 | mood=focused |

### 8.4 安全红线

- rawInput **只提取**文件名/命令名（白名单正则：`"path":"..."`/`"command":"..."`），提取结果过 sanitize 后进统计
- 原文绝不下沉：不进 memories、不进 stats 明细、不进落盘
- code_files 集合上限 10（超限滚动），防无界

## 9. 主动行为（宠物说话）

`view()` 时按优先级产出 pending msg（复用现有 `msg.take()`，前端 12s 轮询收到）：

```
1. crafting 完成（时间到）   → "看！它捏了个幻影朋友"
2. hunger < 25              → "咕……"
3. loneliness > 70          → "你很久没理我了"
4. energy < 20              → 打哈欠
5. fun < 20                 → 扒拉屏幕
6. dazed 中                → "它望着空气发呆"
```

同一 msg 不重复（与上一条不同才发）；优先级 1 的 crafting 完成同时落记忆。

## 13.5 数值系统（v0.2 新增）

> 文案库见独立文档 `docs/宠物文案库.md`（§1 选取机制 / §2-9 全场景文案池 / §10 与数值绑定约定）

### 13.5.1 数值分层

| 层 | 数值 | 特性 | 源 / 汇 |
|:--|:--|:--|:--|
| **A 波动层**（0-100，可涨跌） | hunger / energy / fun / loneliness / happiness(兼容) | 时间驱动衰减 + 事件驱动增减 | 事件收益表（§15.5.3） |
| **B 成长层**（只增不减） | xp（阶段）/ bond（羁绊）/ 统计计数 | 事件累积，有上限 | 任务/工具/互动/感知 |
| **C 衍生层**（计算） | stage / mood / 羁绊称号 / 成长进度 | 由 A+B 推导，不落盘独立值 | derive_mood / stage() |

### 13.5.2 成长曲线（B 层阈值）

**XP 阶段**（保留现有，附达成估算）：

| 阶段 | 阈值 | 累积任务数（≈3xp/完成） | 说明 |
|:--|:--|:--|:--|
| 微光种 Seed | 0 | 0 | 出生 |
| 初生体 Sprout | 25 | ~9 | 约 1 天 |
| 漫游体 Hopper | 90 | ~30 | 约 2-3 天 |
| 陪伴体 Guardian | 220 | ~73 | 约 1 周 |
| 长明体 Luminary | 500 | ~167 | 约 2 周 |

**Bond 羁绊等级**（新增称号体系）：

| 等级 | 阈值 | 称号 | 解锁 |
|:--|:--|:--|:--|
| L0 | 0 | 陌客 | 默认文案 |
| L1 | 100 | 相识 | 主动说话频率 ×1.5 |
| L2 | 300 | 伙伴 | 喂食收益 +10% |
| L3 | 800 | 挚友 | 行为库扩充（新文案池） |
| L4 | 2000 | 共生 | 情绪恢复速度 ×1.5 |
| L5 | 5000 | 羁绊之光 | 稀有事件概率 ×2 |

### 13.5.3 事件收益表（A 层主表，初值待平衡）

| 事件 | hunger | energy | fun | lonely | happy | bond | xp |
|:--|:--:|:--:|:--:|:--:|:--:|:--:|:--:|
| 用户发消息 | -1 | -2 | +2 | **-15** | +1 | +1 | — |
| prompt 完成 | — | -2 | +3 | -10 | +2 | +2 | +3 |
| prompt 失败 | — | — | -2 | +5 | -3 | — | — |
| prompt 超时（发呆） | — | -2 | **+5** | +3 | -1 | — | — |
| 工具成功 | — | -1 | +2 | — | +1 | +1 | +2 |
| 工具失败 | — | — | -2 | — | -2 | — | +1 |
| 喂食 | **+20** | — | +3 | -20 | +7 | +2×贪吃 | — |
| 玩耍 play | -5 | -10 | **+25** | -30 | +4 | +3 | — |
| 每日访问 | — | +20 | — | -10 | — | +1 | — |
| 捏朋友完成 | — | — | +10 | **-40** | +3 | +2 | +2 |
| 编码活动（Code） | -2 | -3 | +4 | -10 | +1 | +1 | — |
| 模式切换（认真） | — | -1 | — | — | +1 | — | — |
| 模型切换 | — | -2 | -2 | +10 | — | — | — |

设计意图：
- **互动是孤独主解药**（发消息 -15、玩耍 -30、捏朋友 -40）——鼓励陪伴
- **发呆是自我恢复**（超时 +5 fun，惩罚转幽默）
- **成功有正循环**（完成/工具成功给 bond+xp），失败不惩罚 bond（只降心情）——不制造"焦虑宠物"
- **编码活动有成本**（-energy）但给 fun——宠物"享受"看代码

### 13.5.4 防刷与收敛

| 机制 | 规则 |
|:--|:--|
| 喂食冷却 | 30s 内重复喂食：收益 ×0.5 → ×0.25 → 0（递减曲线） |
| 玩耍冷却 | 60s 冷却 |
| 每日访问 | 1 次/天有效（现有） |
| 需求惩罚封顶 | 单次事件对单维度影响 ≤ ±30；bond 惩罚单 tick ≤ 1 |
| 收敛 | 全部 A 层 clamp 0-100；B 层上限 xp 999999 / bond 9999 |
| 防"饿死循环" | hunger=0 持续：每 tick bond -0.5，但喂食收益 +50%（雪中送炭加成） |
| 状态值精度 | 内部 u16 存储，DTO 输出 u8（0-100）防浮点漂移 |

### 13.5.5 随机性（低概率调味，可选）

| 事件 | 概率 | 效果 |
|:--|:--|:--|
| 稀有发现 | 1% | "它发现了闪光的代码碎屑" → 双倍 xp 收益 |
| 午夜陪伴 | 22:00-06:00 互动 | bond 收益 ×1.5（时段感知扩展位） |
| 大师时刻 | 连续 5 次工具成功 | "它学着你的样子敲键盘" → fun 全恢复 |

### 13.5.6 数值与感知联动

- Code 活动给"代码碎屑"计数 → 每 50 碎屑自动触发一次喂食级回复（宠物"吃了代码"等于一次免费喂食，但只回 hunger +10）
- 工具成功率（统计推导）> 80% → 宠物"得意"（happy 加成）；< 40% → 宠物"担忧"（窗口事件注入）
