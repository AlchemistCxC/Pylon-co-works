## 2. UI-01：上传背景图后无效

### Bug 点

在 Settings 中选择本地背景图后，路径能够写入主题状态，但界面不显示图片。

涉及字段：

```text
globalBgImage
sidebarBgImage
chatBgImage
inputBgImage
ccBgImage
rightBgImage
statusBgImage
```

### 触发条件

1. 打开 Settings。
2. 选择全局、聊天区、中控区或右栏背景图。
3. 设置状态中能看到本地 Windows 路径。
4. 页面背景仍然为空。
5. 重启后仍然为空。

### 预期

- 选择本地图片后立即显示。
- 设置保存到 `pylon-theme`。
- 重启 Pylon 后仍然显示。
- 远程 URL、浏览器 data URL 和 Tauri 本地文件都能正确处理。

### 根因

`Settings.tsx` 直接把 Tauri 文件选择器返回的本地路径写入 CSS：

```tsx
const selected = await open(...)
if (selected) onChange(selected as string)
```

`App.tsx` 再直接拼接：

```tsx
'--global-bg-image': s.globalBgImage
  ? `url(${s.globalBgImage})`
  : 'none'
```

Windows 路径不是 WebView CSS 可直接读取的资源 URL。路径虽然保存成功，但 CSS `url(C:\\...)` 无法作为可访问图片加载。

### 相关代码

```text
src/components/Settings.tsx:14-29
src/App.tsx:90-148
src/App.tsx:155-162
src/index.css:69-80
src/components/ControlCenter.tsx:161-162, 254-256
src/components/RightPanel.css:1-2
src/store.ts:20-22, 93-107
```

### 解决方案

新增统一的前端背景资源解析函数，禁止各组件自行拼接路径。

规则：

- Tauri 本地路径：使用 `convertFileSrc()` 转换为 WebView 可访问 URL。
- `http://`、`https://`、`data:`、`blob:`：原样保留。
- 空值：返回 `none`。
- 路径解析失败：保留设置状态，但显示可见错误，不静默吞掉。
- 全局背景、区域背景、实时预览共用同一解析函数。

建议入口：

```text
src/backgroundImage.ts
```

### 验收证据

必须同时验证：

- 设置值写入 localStorage。
- CSS 计算值不再是 `none`。
- 图片元素或背景资源实际加载成功。
- reload 后背景仍存在。
- Windows 本地路径带空格时仍可用。

## 3. UI-02：窗口缩小后中控区布局挤成一团

### Bug 点

全屏状态下中控区看似正常，窗口缩小后 EKG、百分比、Token、Model、Mode 等控件互相重叠或聚集成一团。

### 触发条件

1. 使用全屏或宽窗口。
2. 切换到中控区布局。
3. 缩小窗口宽度。
4. 中控区 naturalSize widget 相互挤压。

### 预期

- 窗口缩放前后控件语义顺序不变。
- 控件不互相覆盖。
- input 保持占满可用宽度。
- naturalSize 控件仍然紧贴内容。
- 右栏开关不改变中控区内部坐标。
- 最小窗口尺寸下仍然可读，必要时允许横向压缩或隐藏低优先级控件，但不能重叠。

### 根因

当前实现混用了两种互相冲突的布局模型：

```text
input：百分比绝对定位 + 百分比宽高
其他 widget：百分比绝对定位 + naturalSize 内容宽度
```

`ControlCenter.tsx`：

```tsx
const isNatural = id !== 'input'
```

natural widget 最终只使用：

```tsx
{ left: `${pos.x}%`, top: `${pos.y}%` }
```

`ControlCenter.css`：

```css
.cc-widget.cc-natural {
  container-type:normal;
  width:max-content !important;
  height:auto !important;
}
```

但三个预设仍使用旧的百分比点位，且多个控件的 x 坐标本身已经互相交叉。例如 Claude 预设：

```ts
ekg:    { x: 0,  y: 59, ... }
pct:    { x: 14, y: 55, ... }
tokens: { x: 9,  y: 55, ... }
model:  { x: 17, y: 55, ... }
mode:   { x: 29, y: 54, ... }
```

窗口越窄，百分比锚点之间的实际像素距离越小，但 naturalSize 控件的最小内容宽度不会同步压缩，于是出现覆盖。

### 相关代码

```text
src/components/ControlCenter.tsx:93-140
src/components/ControlCenter.tsx:142-149
src/components/ControlCenter.tsx:195-215
src/components/ControlCenter.tsx:282-338
src/components/ControlCenter.css:18-33
src/presets.ts:102-111
src/presets.ts:165-174
src/presets.ts:228-237
src/store.ts:116-120
```

### 解决方案

不要继续靠手调 x/y 百分比补洞。改为“稳定骨架 + 可选自定义偏移”：

```text
第一层：input 独占一行，占满宽度
第二层：状态控件使用 flex/grid 排列
第三层：model/mode 等控制项按优先级排列
```

设计要求：

- 默认布局使用 CSS Grid 或 Flex，不使用多个 natural widget 的独立百分比绝对定位。
- PropertyPanel 的 X/Y 自定义仍然保留，但自定义应表达偏移，而不是把整个布局重新变成散点坐标。
- `ccPositions` 需要兼容旧数据。
- 旧坐标加载时迁移到新布局模型，不能直接继续解释为旧百分比位置。
- 最小宽度必须通过 Playwright 以多个 viewport 实测。

## 4. UI-03：中控区设置重启后失效

### Bug 点

用户调整控件位置或重置布局，当前进程内看似生效；重启 Pylon 后位置回到旧值或预设值。

### 触发条件

1. 进入中控区布局编辑。
2. 拖动 widget 或通过 PropertyPanel 修改位置。
3. 退出编辑。
4. 重启进程。
5. 控件位置失效。

### 预期

- 拖动位置写入 Zustand 状态。
- Zustand persist 写入 `pylon-theme`。
- 关闭进程后重新启动，位置、隐藏状态、控件样式和缩放值保持。
- 预设切换只在用户明确切换预设时覆盖布局。
- 用户自定义布局不能被运行时默认 override 覆盖。

### 根因

编辑器多个入口直接调用：

```tsx
useStore.setState(...)
```

位置：

```text
src/components/ControlCenter.tsx:314-317
src/components/ControlCenter.tsx:358-359
```

而正式主题更新入口是：

```ts
updateTheme: (partial) => set(partial)
```

此外，CLI 默认布局逻辑仍然在运行时判断：

```tsx
const pos = (!editMode && inputMode === 'cli' && !cliCustomized && CLI_OVERRIDES[id])
  ? CLI_OVERRIDES[id]
  : rawPos
```

这要求 `ccCliCustomized`、`ccPositions`、预设切换和 persist 必须严格同步。当前三套预设均显式写入 `ccPositions`，`setGlobalPreset()` 会把：

```ts
ccCliCustomized: !!(theme as any).ccPositions
```

设为 true。旧 localStorage、预设布局和运行时 override 叠加后，容易出现“本次看到的布局”和“重启后恢复的布局”不一致。

### 相关代码

```text
src/store.ts:68, 195, 249-255, 262-273
src/components/ControlCenter.tsx:228-239
src/components/ControlCenter.tsx:306-317
src/components/ControlCenter.tsx:350-365
src/components/ControlCenter.tsx:392-413
src/presets.ts:102-111, 165-174, 228-237
```

### 解决方案

统一持久化入口：

- 拖拽：使用 `updateTheme()` 或新增 `updateCcPosition()` action。
- 重置：使用 `updateTheme()` 或新增 `resetCcLayout()` action。
- PropertyPanel：使用同一 action。
- 隐藏/显示：使用同一 action。
- 缩放：使用同一 action。
- `ccCliCustomized` 与位置写入必须在一个 `set()` 中完成。

建议新增 action：

```ts
updateCcPosition: (id, partial) => void
resetCcLayout: () => void
setCcHidden: (id, hidden) => void
setCcScale: (id, scale) => void
```

禁止：

```ts
useStore.setState({ ccPositions: ... })
```

作为业务编辑入口。

### 验收证据

必须执行真实 reload 回归：

```text
调整位置
读取 localStorage.pylon-theme
关闭页面或进程
重新加载
读取 DOM getBoundingClientRect()
对比调整前后的坐标
```

只证明 React 当前重渲染，不算持久化通过。

## 5. UI-04：右栏展开后回底部按钮被遮挡

### Bug 点

打开右栏后，ChatView 右下角的回到底部按钮被右栏覆盖，用户无法点击或看不到按钮。

### 触发条件

1. ChatView 有可滚动内容。
2. 回底部按钮显示。
3. 展开右栏。
4. 右栏覆盖按钮。

### 预期

- 右栏打开时，按钮向左移动到右栏左侧。
- 右栏关闭时，按钮回到原位置。
- 按钮不穿透右栏，不应通过提高 z-index 覆盖右栏内容。
- 按钮仍然属于 ChatView 的操作区域。

### 根因

回底部按钮：

```css
.scroll-bottom-btn {
  position:absolute;
  bottom:calc(var(--cc-height, 130px) + 8px);
  right:8px;
  z-index:5;
}
```

右栏：

```css
.right-panel {
  position:absolute;
  top:0;
  right:0;
  bottom:0;
  z-index:40;
}
```

右栏是覆盖层，回底按钮没有跟随 `rightOpen` 做横向偏移。

### 相关代码

```text
src/App.tsx:21-24
src/App.tsx:193-205
src/components/chat/ChatView.tsx:407-409
src/components/chat/ChatView.css:139-147
src/components/RightPanel.css:1-2
```

### 解决方案

将 `rightOpen` 和 `rightWidth` 传给 ChatView，或在 `.main-body` 注入 CSS 变量：

```text
右栏关闭：--chat-right-offset: 0px
右栏打开：--chat-right-offset: calc(var(--right-width) + 8px)
```

回底按钮：

```css
right: calc(8px + var(--chat-right-offset, 0px));
```

不要把 `z-index` 提高到右栏之上。右栏必须继续作为浮层覆盖主区域。

## 6. UI-05：Markdown 编号列表行高设置无效

### Bug 点

普通文本行高可变化，但出现以下内容时，用户设置的行高看起来无效：

```md
1. 第一项
2. 第二项
3. 第三项
```

### 触发条件

- Assistant 输出 Markdown 有序列表。
- 调整聊天区行高或消息行间距。
- 列表项之间的视觉间距没有按设置变化，或出现额外空隙。

### 预期

- 普通段落、列表、推理文本、代码块分别遵守对应的行高语义。
- 列表项目的文字行高由消息行高控制。
- 列表上下 margin 与列表行高分离，不伪装成行高。
- 不通过全局 `!important` 粗暴覆盖 Markdown 结构。

### 根因

当前存在两套行高：

```css
.term {
  line-height:var(--chat-line-height);
}

.term-row-assistant,
.term-row-reasoning {
  line-height:var(--msg-line-height,var(--chat-line-height,1.4));
}
```

列表还有独立 margin：

```css
.term-assistant ol { padding-left:2em; margin:4px 0; }
.term-assistant ul { padding-left:1.5em; margin:4px 0; }
.term-assistant li { margin:2px 0; }
```

ReactMarkdown 会将编号文本转换成真实 `ol > li` 结构。用户看到的垂直间距由：

```text
line-height + ol/ul margin + li margin + Markdown 段落结构
```

共同决定，因此只改父级行高不一定能观察到明显变化。

### 相关代码

```text
src/App.tsx:66-68, 105-117
src/components/Settings.tsx:249-253, 313-322
src/components/chat/ChatView.tsx:416-436
src/components/chat/ChatView.tsx:564-577
src/components/chat/ChatView.css:8, 16-20, 65-74
```

### 解决方案

明确字段职责：

```text
chatLineHeight：聊天容器默认行高
msgLineHeight：消息正文行高
```

然后显式作用到 Markdown 节点：

```css
.term-row-assistant,
.term-row-assistant .term-assistant,
.term-row-assistant .term-assistant p,
.term-row-assistant .term-assistant ol,
.term-row-assistant .term-assistant ul,
.term-row-assistant .term-assistant li {
  line-height:var(--msg-line-height,var(--chat-line-height,1.4));
}

.term-assistant ol,
.term-assistant ul {
  margin-top:0;
  margin-bottom:0;
}

.term-assistant li {
  margin-top:0;
  margin-bottom:0;
}
```

如果产品需要独立控制列表项间距，应新增明确字段，不要继续借用行高字段。

### 验收证据

至少验证：

- 普通单行段落。
- 两段空行文本。
- `1. 2. 3.` 有序列表。
- 无序列表。
- 列表中包含 inline code。
- 列表中包含多行内容。

每组记录改动前后的 `getComputedStyle(lineHeight)` 和元素高度。

## 7. UI-06：三套预设重新设计

### 当前预设

```text
claude  → Claude 风格
```

定位：冰蓝开发终端。

要求：

- Nord 深色蓝灰背景。
- 冰蓝、薄荷绿、暖黄状态色。
- 全等宽 ChatView。
- 工具调用使用连接线和状态菱形。
- 比 Claude Code 有更明显的层次，但不能变成卡片堆叠。
- 中控区采用冰蓝 bar / numeric 组合。

### 相关代码

```text
src/presets.ts:62-258
src/store.ts:93-123
src/components/Settings.tsx:114-137, 326-362
src/components/ControlCenter.tsx:93-140, 195-215
```

- 更新 `PresetName`、label 和三套 theme。
- 修正 `ZONE_FIELDS.cc`，纳入所有当前有效中控区字段：

```text
ccPositions
ccHidden
ccScale
ccCliCustomized
ccStyle
ccVariant
ccHeight
ccBgHeight

```

- 删除或迁移 `ccLayout` 中的旧 `context` 语义；如果保留兼容字段，必须不再作为渲染真值。
- 每个预设提供完整且不重叠的默认布局。
- 不把三套预设强行做成同一套中控区颜色和坐标。
- 预设切换后的布局必须有 reload 验证。

## 8. UI-07：ccLayout 旧字段残留

### Bug 点

store 中仍有：

```ts
ccLayout: ['input', 'context', 'model', 'mode']
```

但当前 ControlCenter 使用 `WIDGET_REGISTRY` 遍历所有控件，不再使用 `context` 作为实际渲染控件。

### 根因

Step 3 拆分 context widget 时更新了注册表和 CSS，但没有完成旧状态字段收敛。

### 影响

- 预设和持久化数据仍可能保存旧 widget 名称。
- 后续开发者可能误以为 `ccLayout` 是实际布局真值。
- 迁移和调试时出现双重真值。

### 解决方案

二选一，不能长期并存：

1. 删除 `ccLayout`，统一以 `ccPositions` / `ccHidden` / 注册表为真值；
2. 保留为兼容字段，但明确标记 deprecated，并增加迁移后不再读取的测试。

推荐方案：保留一次迁移兼容，之后停止读取。

## 9. UI-08：naturalSize 与预设坐标模型冲突

### Bug 点

预设中仍然为 naturalSize 控件提供 `w/h`，但运行时只使用 `x/y`；旧字段会污染迁移、PropertyPanel 和调试判断。

### 根因

中控区经历了百分比缩放、等比缩放、naturalSize 多轮迭代，预设和旧 localStorage 没有统一迁移。

### 解决方案

- input：继续保留 `x/y/w/h`。
- natural widget：运行时只消费 `x/y`；旧 `w/h` 不参与布局。
- 设计一个明确的布局 schema version。
- 启动时迁移旧布局。
- 迁移后再执行 `ensurePositions()`，而不是反过来。

## 10. 交接方式

### 任期内工作流

每次接手任务必须按以下顺序：

1. 先读取本文件。
2. 执行：

```bash

```

3. 确认当前任务对应的 Bug 编号。
4. 读取相关源码，不凭记忆猜测。


### 独立 Bug 原则

- 一个独立根因对应一个修复批次。

## 12. 行为约束与边界

### 必须遵守

- 先读源码，再提出修复。
- 先复现和定位根因，再修改。
- 每个结论必须有文件路径、行号、代码或运行时证据。
- 不把浏览器无 Tauri runtime 的错误当成真实后端 Bug。
- 不把 `npm run build` 通过当成 UI 视觉验收通过。
- 视觉问题必须通过真实 viewport、DOM 尺寸、截图或 Playwright 证据验证。
- 持久化问题必须通过 localStorage + reload / 重启验证。
- CSS 删除或改名时同步清理死代码。
- 设计没有明确授权时维持现有设计，不擅自扩展功能。
- 预设改动必须同时检查 store、persist、CSS variables 和 renderer 消费链。

### 禁止事项

- 禁止修改 `src-tauri/`，除非用户明确授权。
- 禁止修改 Peri 源码，除非用户明确授权。
- 禁止修改 Hermes config.yaml。
- 禁止把 Prism V2 服务作为 Pylon 前置条件。
- 禁止用 `position: absolute` 的临时补丁掩盖中控区布局模型问题。
- 禁止用提高 z-index 的方式修复右栏遮挡。
- 禁止只修改预设颜色而不处理旧布局 schema。
- 禁止添加新的 mock 管理功能；已有 PrismSheet / RightPanel 演示数据必须继续明示并禁用伪操作。
- 禁止把“当前进程内生效”写成“已持久化”。
- 禁止在未验证的情况下关闭 Bug。
