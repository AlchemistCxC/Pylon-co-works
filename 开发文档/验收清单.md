## 3. 跨端架构与验收不变量

### 3.1 三层 Session ID

| 层 | 字段 | 用途 |
|---|---|---|
| React/Zustand | `Session.id` | 前端实体 ID、`pylon-msgs-<id>` owner |
| Pylon/Tauri | `Session.source` / `source` | command/event 路由、Rust sessions map key |
| Peri ACP | `Session.periId` / `sessionId` | 远端 Agent 会话 ID |

规则：

- send/mode/model/cancel/close 使用 `source`。
- load/export 使用 `periId`；export 不使用 source。
- 消息 localStorage 永远使用 `Session.id`，禁止改成 source。
- 所有 event 必须按 `payload.source` 路由；后台会话事件不得因当前不可见而丢弃。

### 3.2 ACP 协议真值

- Tauri JS invoke 参数使用 camelCase；Rust 参数使用 snake_case。
- `initialize` 使用 `clientCapabilities`。
- `session/set_mode` 使用 `modeId`。
- `session/new` 返回完整 `{sessionId,modes,configOptions}`。
- `session/load` 在 response 前 replay history，response 是 replay 完成边界。
- notification variant 使用 snake_case。
- `session/cancel` 是 notification；`session/close` 是 request。
- `session/set_config_option.value` 使用 tagged `ValueId`。
- command reject 字符串错误；用户操作失败必须可见，不得空 catch。

详细 DTO、command 和 event 定义见 API 文档。

### 3.3 生命周期不变量

- 同一 source prompt 串行，不同 source 可并行。
- prompt 等待不持有全局 session creation 或 Agent lifecycle lock。
- timeout 向正确 periId 发 cancel，并继续等待最终 response 最多 30 秒。
- pending 在序列化、写入、response、RPC error、timeout、EOF 和崩溃路径收敛。
- initialize 失败必须 kill + wait child。
- Agent 切换：新 client connect+initialize → 原子 swap → generation +1 → 清 runtime sessions → 新 dispatcher → 关闭旧 client。
- 新 Agent 初始化失败时，旧 Agent、旧 sessions、activeAgent 和 dispatcher 保持不变。
- generation 变化后，旧 Agent response/notification 不得提交到当前状态。
- close 后端失败时，前后端都保留映射/实体以供重试。
- cancel invoke resolve 不代表生成已经结束，最终由 prompt response、`peri:done` 或 `peri:error` 收敛。

### 3.4 前端状态与持久化不变量

- Session 集合由 Zustand store actions 唯一写入。
- `pylon-sessions` 使用 `{version:1,sessions:[...]}`。
- Session 在 `pylon-theme` Profile rehydrate 后再恢复。
- 旧裸数组和 `prism-sessions` 可迁移；有效 Session.id 不得改写。
- 损坏 JSON、未知 schema、缺失/重复 ID 不得导致应用崩溃。
- Profile persona 以 `session.profileId` 为真值，不读取当前全局 Profile 代替。
- mode/model/generating/config 按 source 隔离。
- send 成功后才清空输入和附件。
- Skills/Hooks 未接入运行时，只保留历史字段，不发送给 Agent。

## 10. 已知限制与风险

1. Windows GNU/Tauri test harness 阻塞，需要在可运行 harness 的环境执行 Rust tests。
2. ACP notification 不带 turn/request identity；timeout 取消期间的旧 chunk 只能靠 session/generation 隔离。

5. `agent_status`、`reconnect_agent`、`peri:agent-status` 的完整产品化状态页仍需真实 UI 验收；API 契约已经保留。
6. PrismSheet/RightPanel 当前是明确禁用的演示数据，不是已接真实管理 API。
