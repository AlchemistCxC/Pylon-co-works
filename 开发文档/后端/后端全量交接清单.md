## ACP 协议真值

只能对照以下源码，不得依据已删除或过期 ACP 文档猜测：

```text
F:\A-I\Agent\Peri\peri-tui\src\acp_stdio\

F:\A-I\Agent\Peri\acp-hub\
```

已确认事实：

- initialize 使用 `clientCapabilities`。
- `session/set_mode` 使用 `modeId`。
- `session/new` 返回 `sessionId`、`modes`、`configOptions`。
- `session/load` 在 response 前 replay 历史。
- notification variant 使用 snake_case。
- `session/cancel` 是 notification。
- `session/close` 是 request。
- `set_config_option.value` 使用 tagged `ValueId`。
- 三层 ID 不得混用：前端 `Session.id`、Rust `source`、Peri `periId`。

## 已实施但未完成真实验收的核心不变量

- 同 source/periId prompt 串行，不同 session 可并行。
- timeout 向正确 periId 发送 cancel，并等待取消收敛边界。
- pending 在序列化失败、写入失败、response、RPC error、timeout、EOF 路径收敛。
- initialize 失败 kill + wait 子进程。
- Agent 切换遵循新 client connect+initialize → 原子 swap → 关闭旧 client。
- load 在 response 后校验 client generation，stale load 明确失败。
- cancel、mode、config、persisted list、new、prompt、close 与 export 均在状态提交边界校验 generation。
- notification dispatcher 绑定创建时 generation，swap 后旧 receiver 不再派发事件。
- replay 路由在 load 前建立，load response 是 replay 完成边界。
- close 远端成功后再删除本地映射，失败保留以便重试。

- replay 路由在 load request 前建立，load response 是 replay 完成边界。
- switch/reconnect 使用 client generation/epoch。
- stale generation response/notification 不得提交。
- Agent 切换采用“新 client 完成 connect+initialize → 原子 swap → 关闭旧 client”。
- 新 Agent 启动失败时旧 Agent、activeAgent、sessions 保持可用。
- initialize 失败必须 kill + wait 子进程。
- 不使用固定 sleep、延长 timeout 或吞异常掩盖竞态。

### 5. 错误、进程与安全要求

- spawn 后 initialize 失败必须清理 child。
- stdout EOF 必须唤醒 pending。
- 拒绝空或 sentinel `error` sessionId。
- 不把未知 session 的空 EndTurn 当成功。
- 关键错误返回明确 Err 或进入结构化日志。
- `.ok()`、`let _ =` 只允许有注释的 best-effort cleanup。
- 附件必须限制大小和 MIME，读取失败对用户可见。
- 不支持的附件类型不得显示为成功。
