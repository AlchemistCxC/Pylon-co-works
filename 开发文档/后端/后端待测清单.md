## BUG-P0-01：Prompt timeout cancel 与按会话串行

- 状态：待测试
- 修改范围：`src-tauri/src/lib.rs`、`src-tauri/src/acp.rs`
- 本次实现：
  1. prompt timeout 后发送对应 `periId` 的 `session/cancel`。
  2. 保留原 oneshot receiver，最长等待 30 秒接收 Peri 最终 prompt response；等待期间同 source prompt lock 不释放。
  3. 30 秒内未收敛时移除当前 `source -> periId` 映射并 best-effort `session/close`，阻止同一未知远端 session 被立即复用。
  4. 修复 `call_async` 与 `prepare_prompt` 序列化失败时 pending 未删除的问题。
  5. 新增 timeout cancel/最终响应及正常响应不 cancel 两个 `tokio::test`。
- 自动验证：
  - `unset RUSTFLAGS; cargo check`：exit 0。
  - `git diff --check`：exit 0。
  - `cargo test --lib timeout_sends_cancel_and_waits_for_final_response -- --nocapture`：Cargo 编译成功，但测试二进制未进入 harness，进程状态 `0xc0000139 STATUS_ENTRYPOINT_NOT_FOUND`；shell exit 127，不得视为测试通过。
  - `cargo test --lib response_before_timeout_does_not_send_cancel -- --nocapture`：同上，shell exit 127。
- 必测步骤：
  1. 在可运行 Rust test harness 的环境执行新增两个单元测试。
  2. fake ACP 延迟 prompt 超过 timeout，抓取 `session/cancel` 并确认 `sessionId` 为目标 periId。
  3. cancel 后延迟返回 `stopReason=cancelled`，确认同 source 第二个 prompt 在最终 response 前不会写入。
  4. cancel 后不返回 response，确认 30 秒后本地映射移除、发送 `session/close`，重试创建新 Peri session。
  5. 对不同 source 并发 prompt，确认互不阻塞。
  6. 注入旧 prompt 迟发 chunk，验证前端事件层不会混入新 turn。
- 验收：同 session 不并发；不同 session 可并行；timeout 后 cancel；未收敛 session 不复用；pending 无残留；旧 turn 不污染新 turn。
- 已知限制：通知不携带 turn/request identity；30 秒内 cancel 收敛阶段的旧 chunk 仍会按原 source 发出。prompt lock map 尚未清理。
- 测试结果填写区：待真实 fake ACP/集成测试。

## BUG-P1-05：initialize 失败 child 清理

- 状态：已实施，待测试
- 修改范围：`src-tauri/src/acp.rs`
- 本次实现：新增 `ManagedChild` RAII guard。spawn 后接管 child；initialize RPC error/timeout、pipe 获取失败和其他 connect 失败出口自动执行 `try_wait`，仍运行则 `kill + wait`；成功连接后由 `AcpClient` 持有，显式 kill 与 Drop 使用同一清理逻辑。
- 自动验证：`unset RUSTFLAGS; cargo check` exit 0；`cargo test --lib acp::tests:: --no-run` exit 0；`git diff --check` exit 0。
- 必测步骤：可控 fake ACP 连续制造 initialize error/timeout，检查每次 PID 退出；正常 client Drop 后检查子进程退出。
- 验收：无孤儿子进程；cleanup 错误进入日志。
- 测试结果：待 fake ACP 进程级验收。
