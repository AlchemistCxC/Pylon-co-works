## BUG-P0-01：Prompt timeout cancel 与按会话串行

- 状态：待测试
- 修改范围：`src-tauri/src/lib.rs`、`src-tauri/src/acp.rs`
- 本次实现：
  1. prompt timeout 后发送对应 `periId` 的 `session/cancel`。
  2. 保留原 oneshot receiver，最长等待 30 秒接收 Peri 最终 prompt response；等待期间同 source prompt lock 不释放。
  3. 30 秒内未收敛时移除当前 `source -> periId` 映射并 best-effort `session/close`，阻止同一未知远端 session 被立即复用。
  4. 修复 `call_async` 与 `prepare_prompt` 序列化失败时 pending 未删除的问题。
  5. 新增 timeout cancel/最终响应及正常响应不 cancel 两个 `tokio::test`。
- 自动验证：
  - `unset RUSTFLAGS; cargo check`：exit 0。
  - `git diff --check`：exit 0。
  - `cargo test --lib timeout_sends_cancel_and_waits_for_final_response -- --nocapture`：Cargo 编译成功，但测试二进制未进入 harness，进程状态 `0xc0000139 STATUS_ENTRYPOINT_NOT_FOUND`；shell exit 127，不得视为测试通过。
  - `cargo test --lib response_before_timeout_does_not_send_cancel -- --nocapture`：同上，shell exit 127。
- 必测步骤：
  1. 在可运行 Rust test harness 的环境执行新增两个单元测试。
  2. fake ACP 延迟 prompt 超过 timeout，抓取 `session/cancel` 并确认 `sessionId` 为目标 periId。
  3. cancel 后延迟返回 `stopReason=cancelled`，确认同 source 第二个 prompt 在最终 response 前不会写入。
  4. cancel 后不返回 response，确认 30 秒后本地映射移除、发送 `session/close`，重试创建新 Peri session。
  5. 对不同 source 并发 prompt，确认互不阻塞。
  6. 注入旧 prompt 迟发 chunk，验证前端事件层不会混入新 turn。
- 验收：同 session 不并发；不同 session 可并行；timeout 后 cancel；未收敛 session 不复用；pending 无残留；旧 turn 不污染新 turn。
- 已知限制：通知不携带 turn/request identity；30 秒内 cancel 收敛阶段的旧 chunk 仍会按原 source 发出。prompt lock map 尚未清理。
- 测试结果填写区：待真实 fake ACP/集成测试。

## BUG-P1-06：load 与 Agent switch/reconnect generation 隔离

- 状态：已实施，待测试
- 修改范围：`src-tauri/src/lib.rs`
- 本次实现：AppState 新增原子 `client_generation`；每次成功 swap ACP client 后 generation +1。`load_persisted_session` 在建立临时路由前捕获 generation，load response 后校验；若期间发生 switch/reconnect，则返回明确 stale generation error，并且仅在映射仍指向本次 periId 时移除临时 source，避免删除新代映射。load RPC error 同样采用条件回滚。
- 自动验证：`unset RUSTFLAGS; cargo check` exit 0；`git diff --check` exit 0。
- 必测步骤：fake ACP 阻塞 load response，同时成功 switch/reconnect；放行旧 response 后确认 load 返回 stale error，旧临时映射被清理且不会删除新 Agent 的同 source 映射。
- 验收：不得出现旧 generation load 返回成功；stale 操作明确失败；回滚不破坏新 generation 状态。
- 已知限制：本 Task 当前只收敛审计指定的 load 提交竞态。set/mode/cancel/close/send 的完整 generation 扩展仍需后续生命周期验收后逐项实施，避免扩大当前根因范围。
- 测试结果：待 fake ACP 并发验收。

## BUG-P1-09：Peri 业务失败响应校验

- 状态：已实施，待测试
- 修改范围：`src-tauri/src/acp.rs`、`src-tauri/src/lib.rs`
- 本次实现：`session_id_from` 拒绝缺失、trim 后空字符串和大小写 sentinel `error`，不建立伪 session。新增 `prompt_stop_reason` 校验 prompt response 必须包含受支持的 `stopReason`；`cancelled`、缺字段和未知值走 `peri:error`/Err，不提交 `has_first_prompt`，不 emit 正常 `peri:done`。
- 对照 Peri 真值：stdio `session/new` ThreadStore 失败返回 `sessionId="error"`；未知 session prompt 返回 `stopReason=end_turn`；正常 prompt response 由 `PromptResponse::new` 返回 snake_case stopReason。
- 自动验证：`unset RUSTFLAGS; cargo check` exit 0；`cargo test --lib acp::tests:: --no-run` exit 0；`git diff --check` exit 0。
- 新增测试：拒绝空/error sessionId；接受 end_turn、拒绝 cancelled/缺失 stopReason。
- 必测步骤：fake ACP 返回 `sessionId:error`、空 ID、cancelled、缺失/未知 stopReason，确认不建映射、不提交首轮 persona、不 emit done。
- 验收：业务失败不会显示为成功；错误对用户可见；伪 session 不进入 sessions map。
- 已知限制：Peri stdio 对“未知 session”返回的合法 `end_turn` 与真实零输出成功在 response 结构上不可区分；在不修改 Peri 的前提下，Pylon只能依靠本地 source→periId 映射与 generation 防止发送未知 session。该协议歧义已记录，不伪造额外成功判据。
- 测试结果：待 fake ACP 运行时验收。

## BUG-P1-08：附件真实 ACP ContentBlock

- 状态：已实施，待测试
- 修改范围：`src-tauri/src/acp.rs`、`src-tauri/src/lib.rs`、`src-tauri/Cargo.toml`、`src-tauri/Cargo.lock`
- 本次实现：移除仅拼接 `[Attached: filename]` 的伪附件。后端读取真实文件并构建 ACP prompt blocks：UTF-8 文本作为 text block；PNG/JPEG/GIF/WebP 作为 image block，使用真实 MIME 与 base64 data。单文件限制 10 MiB、单次最多 8 个；目录、读取失败、非 UTF-8 未知文件和不支持 MIME 返回明确 Err，且发生在 `peri:user` emit/ACP 写入前。
- 对照 Peri 真值：`acp_stdio/session/prompt.rs` 直接支持 Text 与 Image ContentBlock，image 读取 `mime_type/data`；Audio/ResourceLink/Resource 当前被忽略，因此后端不伪装为成功。
- 自动验证：`unset RUSTFLAGS; cargo check` exit 0；`git diff --check` exit 0。
- 必测步骤：附件纯文本并核对 Agent 能逐字读取；附件 PNG/JPEG 并抓取 JSON-RPC image block；测试 >10MiB、目录、PDF/ZIP、缺失文件、超过8个附件，确认明确失败且不发送 prompt。
- 验收：附件内容而非文件名进入 Peri；MIME/大小限制生效；失败用户可见；不支持类型不显示为成功。
- 已知限制：路径仍来自前端 Tauri dialog 的字符串，当前 command 无不可伪造的 capability token；后端通过文件类型、大小、数量与读取结果限制风险，但任意路径信任边界仍需 Tauri scoped FS/capability 方案才能完全收敛。
- 测试结果：待真实 Tauri + Peri 集成验收。

## BUG-P2-05：导出 replay 完成边界

- 状态：已实施，待测试
- 修改范围：`src-tauri/src/acp.rs`、`src-tauri/src/lib.rs`
- 本次实现：ACP reader 先把每条消息送入 broadcast，再把 response 送入对应 pending oneshot。由此 `session/load` future 返回时，Peri 在 response 前发送的全部 replay notification 已进入 broadcast；export 移除固定 1500ms sleep，直接以 load response 为确定性完成边界后停止 collector。
- 对照 Peri 真值：`acp_stdio/session/create.rs::handle_load` 在 responder 前依次 replay history、发送 config update，随后才发送 LoadSessionResponse。
- 自动验证：`unset RUSTFLAGS; cargo check` exit 0；`git diff --check` exit 0。
- 必测步骤：构造大量 replay，确认 response 前的全部 broadcast 消息被 collector 接收；验证不再等待固定1.5秒；检查 user/assistant/reasoning/tool/metadata 导出完整性。
- 验收：response 是唯一 replay 边界；无固定 sleep；不静默截断。
- 已知限制：无固定 sleep；formatter 已覆盖 user/assistant/reasoning/tool/metadata；broadcast Lagged/Closed 会返回明确错误。仍需大历史真实集成验收确认 collector 调度完整性。
- 测试结果：待大历史 replay 集成验收。
