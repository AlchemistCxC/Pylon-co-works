### BUG-P0-01

- 根因：timeout 原实现只删除本地 pending 并立即释放同 source prompt lock；虽然发送了 cancel，但未等待 Peri 最终 response，重试可能与尚未收敛的旧任务重叠。`call_async/prepare_prompt` 的序列化失败路径还会遗留 pending。
- 实现摘要：抽出 `wait_prompt_with_cancel`；timeout 后发 `session/cancel` 并继续等待最终 response 30 秒；等待期间保留 per-source lock。未收到最终 response 时移除匹配的本地 session 映射并 best-effort `session/close`，使后续重试创建新 session。序列化失败会删除 pending。
- 修改文件：`src-tauri/src/acp.rs`、`src-tauri/src/lib.rs`、`开发文档/后端/后端待测清单.md`、`开发文档/后端/后端交接文档.md`。
- 对照 Peri 真值：
  - `F:\A-I\Agent\Peri\peri-tui\src\acp_stdio\session\prompt.rs`：prompt 后台执行，cancel token 注册到 session。
  - `F:\A-I\Agent\Peri\peri-tui\src\acp_stdio\session\control.rs`：`session/cancel` 按 sessionId 触发 token。
  - `F:\A-I\Agent\Peri\peri-tui\src\acp_stdio\session\prompt_exec.rs`：取消后仍发送最终 `PromptResponse`，随后清理 cancel token。
  - `F:\A-I\Agent\Peri\peri-tui\src\acp_server\mod.rs`：参考 per-session prompt serialization。
- 并发/生命周期不变量：同 source prompt lock 覆盖正常 response 或 cancel 收敛边界；不同 source 仍可并行；未收敛的 periId 不再被本地映射复用；timeout/cancel 路径删除 pending。
- 新增测试：`timeout_sends_cancel_and_waits_for_final_response`、`response_before_timeout_does_not_send_cancel`。
- 验证证据：
  - `unset RUSTFLAGS; cargo check` exit 0。
  - `git diff --check` exit 0。
  - 两个 `cargo test --lib ...` 均完成编译，但 test binary 启动失败，进程状态 `0xc0000139 STATUS_ENTRYPOINT_NOT_FOUND`，shell exit 127，未进入 test harness。
