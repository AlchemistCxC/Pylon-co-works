### BUG-P0-01

- 根因：timeout 原实现只删除本地 pending 并立即释放同 source prompt lock；虽然发送了 cancel，但未等待 Peri 最终 response，重试可能与尚未收敛的旧任务重叠。`call_async/prepare_prompt` 的序列化失败路径还会遗留 pending。
- 实现摘要：抽出 `wait_prompt_with_cancel`；timeout 后发 `session/cancel` 并继续等待最终 response 30 秒；等待期间保留 per-source lock。未收到最终 response 时移除匹配的本地 session 映射并 best-effort `session/close`，使后续重试创建新 session。序列化失败会删除 pending。
- 修改文件：`src-tauri/src/acp.rs`、`src-tauri/src/lib.rs`、`开发文档/后端/后端待测清单.md`、`开发文档/后端/后端交接文档.md`。
- 对照 Peri 真值：
  - `F:\A-I\Agent\Peri\peri-tui\src\acp_stdio\session\prompt.rs`：prompt 后台执行，cancel token 注册到 session。
  - `F:\A-I\Agent\Peri\peri-tui\src\acp_stdio\session\control.rs`：`session/cancel` 按 sessionId 触发 token。
  - `F:\A-I\Agent\Peri\peri-tui\src\acp_stdio\session\prompt_exec.rs`：取消后仍发送最终 `PromptResponse`，随后清理 cancel token。
  - `F:\A-I\Agent\Peri\peri-tui\src\acp_server\mod.rs`：参考 per-session prompt serialization。
- 并发/生命周期不变量：同 source prompt lock 覆盖正常 response 或 cancel 收敛边界；不同 source 仍可并行；未收敛的 periId 不再被本地映射复用；timeout/cancel 路径删除 pending。
- 新增测试：`timeout_sends_cancel_and_waits_for_final_response`、`response_before_timeout_does_not_send_cancel`。
- 验证证据：
  - `unset RUSTFLAGS; cargo check` exit 0。
  - `git diff --check` exit 0。
  - 两个 `cargo test --lib ...` 均完成编译，但 test binary 启动失败，进程状态 `0xc0000139 STATUS_ENTRYPOINT_NOT_FOUND`，shell exit 127，未进入 test harness。
- 未验证：真实 fake ACP cancel 参数抓取；同 source 等待收敛、不同 source 并发；迟发 notification 的 turn 隔离。
- 剩余风险：ACP notification 没有 request/turn identity，30 秒收敛期的旧 chunk 仍按原 source 路由；prompt lock map 未清理；未实现通用 Agent generation。

### BUG-P1-05

- 状态：待测试
- 根因：`AcpClient::connect` 在 spawn 后直接使用裸 `Child`。stdin/stdout/stderr 获取失败或 initialize 返回 RPC error/timeout 时，`?` 提前返回，`Child` 的默认 Drop 不会终止或 wait 子进程，导致 Peri 孤儿进程。
- 实现摘要：新增 `ManagedChild` RAII guard。spawn 后立即接管 child；所有 connect 失败出口自动执行 `try_wait`，仍运行则 `kill + wait`；连接成功后 guard 作为 `AcpClient` 字段继续管理，显式 `kill()` 与 Drop 复用同一清理逻辑。
- 修改文件：`src-tauri/src/acp.rs`、后端待测清单、后端交接文档。
- 对照 Peri 真值：
  - `F:\A-I\Agent\Peri\peri-tui\src\acp_stdio\mod.rs`：initialize 是连接建立后的首个 ACP request。
  - `F:\A-I\Agent\Peri\peri-tui\src\acp_stdio\transport.rs`：initialize handler 通过 responder 返回响应。
  - `F:\A-I\Agent\Peri\peri-tui\src\acp_stdio\init.rs`：initialize 前 Peri 已完成 provider、MCP、插件、ThreadStore 等进程级初始化，失败/超时期间子进程可能保持运行。
- 生命周期不变量：spawn 后任意失败出口均拥有 child cleanup guard；kill 后必须 wait；已退出 child 不重复 kill；成功 client 的 Drop 也不遗留进程。
- 新增测试：未新增可运行进程测试；当前 Windows GNU/Tauri test binary 无法进入 harness。
- 自动验证：
  - `unset RUSTFLAGS; cargo check`：exit 0。
  - `cargo test --lib acp::tests:: --no-run`：exit 0，测试二进制编译成功。
  - `git diff --check`：exit 0。
- 必测步骤：
  1. 使用可控 fake ACP 子进程，收到 initialize 后返回 JSON-RPC error，再连续调用 `AcpClient::connect` 5 次。
  2. 每次失败后检查 fake 子进程 PID 已退出，且不存在累积进程。
  3. fake ACP 不响应 initialize，等待 30 秒 RPC timeout，确认进程被 kill + wait。
  4. fake ACP 正常 initialize 后 Drop client，确认子进程退出。
- 验收：initialize error/timeout、pipe 获取失败、正常 client Drop 均不遗留子进程；cleanup 错误进入日志。
- 测试结果填写区：待 fake ACP 进程级验收。

### BUG-P1-04

- 状态：待测试
- 根因：原 `switch_agent/reconnect_agent` 在连接新 Agent 前先 kill 旧 client。目标 exe 无效或 initialize 失败时，旧 Agent 已不可用，但 activeAgent 与 sessions 仍指向旧状态，应用进入瘫痪状态。
- 实现摘要：新增独立 `agent_lifecycle` 锁；switch/reconnect 先完成新 `AcpClient::connect`，仅成功后调用 `replace_agent_client` 原子替换。swap 后提交 activeAgent（switch）、清空旧 sessions、重启 notification dispatcher，再 kill+wait 旧 client。失败发生在 swap 前，不修改旧状态。
- 修改文件：`src-tauri/src/lib.rs`、后端待测清单、后端交接文档。
- 对照 Peri 真值：`AcpClient::connect` 只有在 Peri initialize response 成功后返回可用 client；因此该返回值是两阶段切换的 prepare 完成边界。
- 并发/生命周期不变量：switch/reconnect 互斥；旧 client 在新 client initialize 完成前保持可用；activeAgent/sessions 仅在 swap 成功后提交；旧 child 在 swap 后 kill+wait。
- 自动验证：`unset RUSTFLAGS; cargo check` exit 0；`git diff --check` exit 0。
- 未验证：无效 exe/initialize error 下旧 Agent 继续 prompt；成功切换真实进程顺序。
- 剩余风险：当前其他 ACP 操作未捕获 generation；成功 swap 时旧 operation 的 stale response/notification 隔离属于 BUG-P1-06。
