## 2. 已建立的前端基础设施

### 会话消息与 replay

- `messagePersistence.ts`：消息 owner 与当前 render session guard。
- `sessionEventState.ts`：按 source 更新消息与 generating 集合。
- `replayState.ts`：replay/live 判定、load 成功/失败历史选择、缓存序列化。
- ChatView 中消息按 `Session.source` 分区；localStorage key 仍按 `Session.id`。

### Session model/mode

- `sessionModel.ts` / `sessionModelState.ts`：统一 model setter、乐观更新、失败回滚。
- `sessionMode.ts` / `sessionModeState.ts`：统一 mode setter、按 source 分区、失败回滚。
- 后端调用必须始终先完成 `Session.id → Session.source`。

### Profile 与发送事务

- `profilePersistence.ts`：Profile schema version 与 hydrate 归一化。
- `sendTransaction.ts`：只有 send 成功才清空输入与附件。

### UI 数据格式化

- `toolStatus.ts`：`pending/in_progress/completed/failed/error` 映射。
- `tokenFormat.ts`：token count 与 cache read count 格式化。

## 3. 三层 Session ID

禁止混用：

- `Session.id`：前端本地实体 ID、localStorage key。
- `Session.source`：Rust sessions map key、Tauri command/event 的 source。
- `periId`：Peri ACP sessionId，由后端管理。

所有 Tauri 会话调用先显式解析 `Session.id → Session.source`。消息、generating、mode、model、commands 等状态按 source 隔离。
