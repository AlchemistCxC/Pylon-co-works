## 3. 剩余两个 Bug

### BUG-P3-01：Session 持久化单一所有权

当前事实：

- Zustand `partialize` 已排除 `sessions`，所以不是 `pylon-theme` 与 `pylon-sessions` 同时保存同一集合。
- 真正问题是多个组件直接读写 `localStorage['pylon-sessions']`：
  - `src/store.ts`
  - `src/components/Sidebar.tsx`
  - `src/components/SessionSettings.tsx`
  - `src/components/chat/ChatView.tsx`
- 当前没有明确的 Session schema version、migration 和唯一写入 API。

接任者先定契约再改代码：

1. 确定 `pylon-sessions` schema 与 version。
2. 定义 migration，至少兼容旧字段缺失、悬空 profileId、旧 key `prism-sessions`。
3. 将读写集中到单一 repository/store action，组件不得直接 `localStorage.setItem`。
4. 消息缓存 `pylon-msgs-<Session.id>` 继续以本地 Session.id 为 owner，不与 `Session.source` 混用。
5. 增加 hydrate/migration/多入口更新回归测试。

未定契约前不要直接清理 localStorage 代码。

### BUG-P3-02：静默错误处理

该编号不是单一根因，必须拆成独立子任务：

1. Agent 切换失败：Settings 显示错误，旧 Agent 和 sessions 不得提前清空。
2. new/load session 失败：当前会话显示可操作错误，明确 fallback 语义。
3. cancel_prompt 失败：错误可见，generating 状态不能假收敛。
4. close_session 失败：确定“保留并重试”或“本地删除 + pending close”策略。
5. localStorage 写入失败：至少保留诊断信息；不能把关键持久化失败完全吞掉。
6. 仅 cleanup、浏览器 fallback、可选语法高亮等 best-effort 路径允许吞错，但必须有注释说明。

每条子任务独立根因、独立测试、独立 commit，禁止一次性全仓替换 `.catch(() => {})`。

## 5. 关键前端架构

### 三层 Session ID

禁止混用：

- `Session.id`：前端本地实体 ID、`pylon-msgs-*` key。
- `Session.source`：Rust sessions map key、Tauri command/event 路由 key。
- `periId`：Peri ACP `sessionId`，由后端维护。

所有 Tauri 会话调用先显式完成 `Session.id → Session.source`。

### 会话事件和历史

- `src/components/chat/messagePersistence.ts`：消息 owner guard。
- `src/components/chat/sessionEventState.ts`：按 source 更新消息和 generating 集合。
- `src/components/chat/replayState.ts`：replay/live、load 成功/失败、本地 fallback。
- `ChatView.tsx`：当前显示按 source 订阅，后台事件仍持久化到对应 Session.id。

### Model / Mode / Profile / 发送

- `sessionModel.ts`、`sessionModelState.ts`：model 乐观更新和失败回滚。
- `sessionMode.ts`、`sessionModeState.ts`：mode 按 source 隔离和失败回滚。
- `sessionProfile.ts`：按 `session.profileId` 解析 persona；Profile 切换时清理错配 activeSession。
- `sendTransaction.ts`：只有发送成功才清空输入和附件。
- `sessionRuntime.ts`：`send_message` payload 白名单，不发送未接入的 Skills/Hooks。

### ACP 类型边界

- `src/components/chat/acpTypes.ts`：SessionResponse、ConfigOption、SessionUpdate 等类型与解析器。
- 协议扩展字段使用 `unknown`，不得重新扩大成 `any`。
- `ChatView.tsx` 已移除主要 `invoke<any>` / `listen<any>`。

### 主题和消息样式

- `App.tsx` 显式订阅主题字段并注入 CSS variables。
- 消息设置由 `--msg-font`、`--msg-text`、`--msg-line-height` 和 `data-msg-style` 驱动。
- body/html 伪元素需要的全局 CSS 变量必须注入 `document.documentElement`，不能只放 `.app`。

### 中控区

- 仅 input 使用百分比宽高；其他 widget 为 naturalSize。
- box 只负责位置移动，配置统一走 PropertyPanel。
- `ControlCenter.tsx` 必须保留 `import './chat/StatusBar.css'`。
- CLI 默认 override 仅在 `ccCliCustomized === false` 时生效。
- `ccStyle` 是 wave/bar/numeric 的唯一 UI 真值；不要恢复与其冲突的 tokenDisplay 设置入口。

### 代码高亮

- `src/components/chat/codeHighlight.ts` 按语言动态加载 grammar，并按 scope 缓存 highlighter。
- 不要恢复 `createStarryNight(common)`；它会重新生成约 9 MB chunk。
- 未支持语言返回纯文本 fallback。
