## BUG-P2-06：Session Skills/Hooks 明确标记未接入

- 状态：已实施，待真实 UI 测试
- 类型：跨端
- 修改范围：`SessionSettings.tsx`、`SessionSettings.css`、`Settings.tsx`、`InputBar.tsx`、`sessionRuntime.ts`、`scripts/test-session-runtime.mts`
- 根因：会话设置允许编辑并持久化 `skills/hooks`，但 `new_session`、`load_persisted_session` 与 `send_message` 均没有对应运行时链路，界面把仅存 localStorage 的字段表现成可用功能。
- 前端处理：
  - 移除 Skills/Hooks 的新增、删除与保存控件。
  - 会话设置明确显示“未接入运行时”，保留历史字段但不编辑、不发送，避免破坏已有 localStorage 数据。
  - 设置页入口同步说明未接入状态。
  - `send_message` payload 收敛到 `buildSendMessagePayload`，自动化断言不包含 `skills/hooks`。
- 自动验证：
  - `node --experimental-strip-types scripts/test-session-runtime.mts`：exit 0，确认 `source/content/persona/sessionPrompt/attachments` 正常，且 payload 不含 `skills/hooks`。
  - `node --experimental-strip-types scripts/test-send-transaction.mts`：exit 0，发送成功/失败事务回归通过。
  - `npm run build`：exit 0，3306 modules transformed。
  - `git diff --check -- src scripts`：exit 0。
  - `grep` 检查：`setSkills/setHooks/newSkill/newHook/chip-row/chip-add` 无残留；Chat/InputBar 运行时链无 `skills/hooks` 引用。
  - 浏览器 UI 实测：Vite 页面创建会话并打开会话设置，dialog 文本包含 `Skills / Hooks`、`未接入运行时` 与后端链路说明，且没有 Skills/Hooks 编辑控件。
- 运行时步骤：
  1. 打开任一会话设置，确认 Skills/Hooks 不再可编辑，并显示“未接入运行时”。
  2. 检查设置页“当前会话设置”提示同步标明未接入。
  3. 使用含历史 `skills/hooks` 的 localStorage 会话保存其他字段，确认历史值未被覆盖或删除。
  4. 正常发送消息，确认 Prompt 与附件链路不受影响。
- 验收：产品不再把 Skills/Hooks 冒充为可用功能；历史配置不破坏；发送 payload 明确不携带未接入字段。
- 后端依赖：若后续后端建立会话级 Skills/Hooks 到 Peri session/frozen context 的真实契约，再恢复编辑入口并增加端到端测试。
- 测试结果：自动化、build 与浏览器 UI 提示通过；真实 Tauri 历史数据保留和正常发送待填写。
