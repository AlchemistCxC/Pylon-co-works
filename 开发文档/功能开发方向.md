# 功能开发方向

> 本文描述用户提出的新增功能、准确边界与可能实现方法。
>
> 事实来源：当前 `src/`、当前 Tauri commands、当前 ACP 前端类型。ACP 或具体 Agent 未暴露的能力，不按“已支持”描述。

## 总体目标

把 Pylon 的设置体系从“主题外观设置”扩展为三个明确层级：

1. 显示层：中控区与 Spinner 的视觉和文案。
2. 会话层：会话 Prompt、会话配置项、预设选择。
3. Agent 层：Agent 状态、可暴露的 ACP 配置、MCP、全局 Prompt、热重载。

三个层级必须使用不同的数据真值和生命周期，不能把所有配置都塞进 `ThemeSettings`。

## 方向一：中控区信息字体增大

### 功能描述

中控区的上下文百分比、Token 数、Model、Mode 等信息当前使用 12px 基础字号，视觉上略小。需要整体稍微增大，同时保留每个 widget 的独立缩放。

### 当前实现

- `src/components/ControlCenter.css:28-32`

```css
.cc-status-row {
  font-family: var(--mono);
  font-size: 12px;
}
```

- 每个 natural widget 另有 `ccScale[id]` 百分比缩放。

### 推荐实现

1. 新增主题字段：

```ts
ccStatusFontSize: number
```

建议默认值从 12 调到 13 或 14，不直接写死到 CSS。

2. `App.tsx` 注入：

```ts
'--cc-status-font-size': `${s.ccStatusFontSize}px`
```

3. CSS 使用：

```css
.cc-status-row {
  font-size: var(--cc-status-font-size, 13px);
}
```

4. Settings 的“中控区”页增加“信息字号”，范围建议 11-20px。
5. `ccScale` 保留，作为单个控件相对于基础字号的缩放。

### 验收标准

- 修改字号后 pct/tokens/model/mode 同步变大。
- 独立 widget scale 仍生效。
- 900px、1200px、1600px 宽度下不重叠。
- 字号变化不影响输入栏高度。

## 方向二：Spinner 字符集、运行文案与终止符号

### 功能描述

Spinner 设置拆分为三个可独立配置的资产：

1. 动画帧字符集：如 `✳✴✵`、`|/-\\`、Braille 字符等。
2. 生成中文案字符集：当前全是中文成语，增加英文和自定义文案。
3. 完成/终止标记：用户可选择生成完成、用户取消、错误时的符号。

### 当前实现

- `src/components/chat/spinnerFrames.ts`
  - `sparkles` 字符串按 Unicode code point 拆成动画帧。
- `src/components/chat/GenerationFooter.tsx:5-9`
  - `IDIOMS` 为硬编码中文数组。
- `src/components/chat/GenerationFooter.tsx:64-67`
  - 完成态使用本轮 spinner 的 `completedFrame`。
- `store.ts`
  - 只有 `sparkles`、`spinnerColor`、`spinnerSize`。

### 准确的数据模型

不要继续往 `sparkles` 一个字符串里塞所有语义。建议：

```ts
type SpinnerLanguage = 'zh' | 'en' | 'custom'

type SpinnerPresetId =
  | 'sparkles'
  | 'ascii-line'
  | 'braille'
  | 'dots'
  | 'custom'

interface SpinnerSettings {
  framePreset: SpinnerPresetId
  customFrames: string
  language: SpinnerLanguage
  customVerbs: string[]
  doneMarker: string
  cancelledMarker: string
  errorMarker: string
  color: string
  size: number
  intervalMs: number
}
```

如果不想一次重构 store，第一阶段可先增加：

```ts
spinnerVerbSet: 'zh' | 'en' | 'custom'
spinnerCustomVerbs: string
spinnerDoneMarker: string
spinnerCancelledMarker: string
spinnerErrorMarker: string
```

### 内建字符集建议

```ts
const SPINNER_FRAME_PRESETS = {
  sparkles: '✳✴✵✶✷✸✹✺✻✼❃❊',
  asciiLine: '|/-\\',
  braille: '⠋⠙⠹⠸⠼⠴⠦⠧⠇⠏',
  dots: '⠁⠂⠄⡀⢀⠠⠐⠈',
}
```

### 文案字符集建议

中文：保留现有成语集。

英文：

```ts
[
  'Thinking',
  'Working',
  'Analyzing',
  'Reading context',
  'Planning next step',
  'Running tools',
  'Composing response',
]
```

自定义：设置页使用“一行一条”的 textarea，保存时 trim、去空行、去重。

### 终止标记

明确三种状态：

- 正常完成：`doneMarker`
- 用户取消：`cancelledMarker`
- 失败：`errorMarker`

不能继续让完成态随机取 spinner 当前帧。`completionFrame()` 当前直接调用 `frameAt()`，因此完成标记不稳定；应改为状态驱动的固定 marker。

### 设置页 UI

建议放在“终端 → Spinner”分组：

- 动画样式：下拉预设 + 实时预览
- 帧字符：自定义输入
- 文案语言：中文 / English / 自定义
- 自定义文案：textarea
- 完成符号
- 取消符号
- 错误符号
- 速度、颜色、字号

### 兼容与迁移

已有 `sparkles` 继续作为 `customFrames` 的迁移来源。旧用户不应因新 schema 丢失当前 Spinner 样式。

## 方向三：Agent ACP 设置面板

### 功能描述

在设置页显示并修改当前 Agent 通过 ACP 暴露的配置项，不把 UI 写死为“model/mode”两项。

用户期望包括：

- MCP Server
- 全局 Prompt
- 其他 Agent 暴露的 config options
- 当前 Agent 状态
- 热重载/重连

### 当前能力边界

当前前端已接入：

- `new_session` 返回 `configOptions`
- `config_option_update`
- `set_config_option(source, key, value)`
- `set_mode(source, mode)`
- `list_agents`
- `switch_agent`

当前 Tauri 还提供：

- `agent_status`
- `reconnect_agent`
- `reload_agents`

但前端 Settings 尚未接入后三项。

当前 ACP new/load 参数把 MCP 写死为空数组：

```rust
"mcpServers": []
```

因此 MCP 不是现有可编辑能力，必须先扩展请求数据模型和后端 command，不能只做前端表单。

### 配置渲染架构

1. 保存完整 `configOptions`，不要只抽取 model：

```ts
sessionConfigOptions: Record<string, ConfigOption[]>
```

2. 按 ACP option type 动态渲染：

- `select` → `<select>`
- `boolean` → switch
- `string` → input
- `number` → number input
- 未知 type → 只读 JSON 或标记不支持

3. 所有修改走统一函数：

```ts
setSessionConfigOption(source, configId, nextValue)
```

函数负责：

- 乐观更新
- 调用 `set_config_option`
- 解析 response/config update
- 失败回滚
- 展示运行时错误

4. `model` 和 `mode` widget 最终也应复用同一配置层，避免 Settings、ModelWidget、ModeWidget 各自维护不同逻辑。

### Agent 状态 UI

Agent 页顶部显示：

- 当前 Agent
- connected / crashed / reconnecting
- transport
- 可选工作目录
- 最近错误

页面加载时调用 `agent_status`；同时监听 `peri:agent-status`。

### 重要边界

ACP config option 通常是 session 级，不等于 Agent 全局配置。设置页必须明确标注作用域：

- Agent 全局
- Profile 默认
- 当前 Session

不允许把 session config 的修改冒充成 Agent 全局设置。

## 方向四：MCP Server 管理

### 功能描述

允许用户在设置页维护 MCP Server，并在创建/恢复会话时传给 Agent。

### 当前缺口

当前 `AcpClient::new_session()` 与 load 参数都写死：

```json
"mcpServers": []
```

因此需要跨层实现，单改前端无效。

### 建议数据模型

```ts
interface McpServerPreset {
  id: string
  name: string
  transport: 'stdio' | 'http' | 'sse'
  enabled: boolean
  command?: string
  args?: string[]
  env?: Record<string, string>
  url?: string
  headers?: Record<string, string>
}
```

### 作用域

建议支持：

- 全局 MCP 列表
- Profile 默认启用集合
- Session 覆写启用集合

最终 session 请求采用：

```text
全局可用服务器
→ Profile 默认选择
→ Session 增删覆写
→ 构造 session/new 或 session/load 的 mcpServers
```

### 安全边界

- 环境变量与 Header 可能含 secret，日志和导出必须脱敏。
- 前端不要把 secret 注入主题 store/localStorage。
- stdio command/args 必须明确展示，不允许隐式执行未知路径。
- HTTP URL 必须校验 scheme。

### 可能涉及的文件

前端：

- `src/store.ts` 或独立 `agentSettingsStore.ts`
- `src/components/Settings.tsx`
- 新建 `src/components/settings/McpServersEditor.tsx`
- `src/components/chat/sessionRuntime.ts`

后端：

- `src-tauri/src/acp.rs`
- `src-tauri/src/lib.rs`
- 持久化配置模块

## 方向五：全局 Prompt 与 Prompt 预设库

### 功能描述

用户希望：

1. 设置当前 Agent 的全局 Prompt。
2. 保存、修改、命名多个 Prompt 预设。
3. 在会话设置中直接选择 Prompt 预设。
4. 会话仍可在预设基础上继续编辑。

### 必须区分的 Prompt 层级

建议明确四层：

```text
Agent Global Prompt
→ Profile Persona
→ Session Prompt Preset
→ Session 临时编辑/覆写
```

实际拼接或覆盖规则必须显式配置，不使用隐式魔法。推荐第一版采用简单覆盖语义：

- Session Prompt 非空：使用 Session Prompt。
- 否则使用所选 Prompt Preset。
- 未选预设：使用 Profile Persona。
- Agent Global Prompt 由 Agent 自己支持时在更外层生效。

如果要拼接，必须在 UI 明确显示最终 Prompt 预览。

### Prompt 预设数据模型

```ts
interface PromptPreset {
  id: string
  name: string
  content: string
  description?: string
  createdAt: number
  updatedAt: number
}
```

Session 增加：

```ts
promptPresetId?: string
sessionPrompt: string
```

### 设置页功能

“Prompt 预设”管理器应支持：

- 新建
- 命名
- 修改
- 复制
- 删除
- 搜索
- 导入/导出 JSON
- 查看被哪些 Profile/Session 使用

### 会话设置功能

会话 Prompt 区包含：

- Prompt 预设下拉框
- “使用 Profile 默认”选项
- Prompt 内容编辑器
- “恢复预设内容”按钮
- “另存为预设”按钮
- 最终有效 Prompt 预览

### 持久化建议

Prompt preset 是用户资产，不应塞进 ThemeSettings。建议独立 versioned storage：

```text
pylon-prompt-presets
```

并建立独立 normalize/migration 模块。

### 发送链路

当前 `sessionRuntime.ts` 会发送：

```ts
sessionPrompt: session.sessionPrompt || ''
```

实现预设后应使用纯函数构造：

```ts
resolveEffectiveSessionPrompt({
  session,
  profile,
  promptPresets,
})
```

并为覆盖、空值、删除预设、旧 session migration 写回归测试。

## 方向六：Agent 热重载

### 功能描述

用户希望无需重启 Pylon 即可重新加载/重连当前 Agent。

### 当前可用命令

后端当前存在：

- `reload_agents(configPath?)`：重新读取 Agent registry。
- `reconnect_agent()`：重建当前 Agent ACP client。
- `switch_agent(name)`：连接另一个 Agent。
- `agent_status()`：读取当前 Agent 与 crashed 状态。

### “热重载”应拆成两个操作

1. 重新加载 Agent 配置：

```text
reload_agents
→ list_agents
→ 更新 Agent 列表
```

2. 重连当前 Agent：

```text
reconnect_agent
→ 等待 peri:agent-status connected
→ 清理失效运行时 session 映射
→ 提示用户重新载入历史 session
```

不要把两者合并成一个含义不清的“热重载”按钮。

### UI 建议

Agent 页增加：

- 重新读取 Agent 配置
- 重连当前 Agent
- 状态指示器
- Agent 配置文件路径
- 最后重连时间
- 错误详情

### 会话影响

当前后端替换 ACP client 时会清空运行时 session map。前端必须明确处理：

- 当前 active session 失效。
- 本地 session 资产是否保留。
- 用户再次点击历史 session 时执行 load。
- 正在生成的任务全部收敛为中断/失败。

推荐：保留前端 session 列表，只清理 runtime mapping 和 generating 状态；不要直接删除用户会话资产。

### 验收标准

- Agent 崩溃后可通过“重连”恢复，不重启应用。
- 重连失败时前端保持 error 状态并可重试。
- 热重载不会静默删除本地会话列表。
- reload 后 Agent 列表立即更新。
- 所有旧 generation source 被清理。

## 推荐开发阶段

### Phase 1：状态与 UI 基础

- 中控区基础字号设置。
- Spinner 帧预设、英文文案、完成/取消标记。
- SessionSettings UI 重排。
- PromptPreset 独立持久化模型。

### Phase 2：会话级 ACP 配置

- 保存完整 configOptions。
- 动态渲染 ACP config option。
- 统一 model/mode/config option 更新链。
- 会话设置选择 Prompt 预设。

### Phase 3：Agent 生命周期

- agent_status UI。
- reconnect_agent。
- reload_agents + list_agents 刷新。
- Agent 切换/重连后的 session 状态收敛。

### Phase 4：MCP 与 Agent 全局 Prompt

- 明确 Agent 对全局 Prompt 的协议支持。
- MCP server 数据模型和安全存储。
- session/new/load 注入 MCP servers。
- 作用域合并、导入导出与密钥脱敏。

---

## 非目标与边界

- 不把 Agent/MCP/Prompt 资产塞进主题预设。
- 不把 ACP session option 冒充为 Agent 全局 option。
- 不在前端表单完成但后端未接线时显示为“可用”。
- 不用硬编码字段列表假装支持所有 Agent。
- 不在热重载时静默删除用户本地会话资产。
- 不在 localStorage 明文持久化 MCP secret。
